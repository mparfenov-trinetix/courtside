# Courtside: project notes for Claude Code

Practice app, not shipping to stores. The owner is an experienced React Native
developer who wants to explore animations and native features.

## Stack
- Expo SDK 58, React Native 0.88, React 19.3, React Compiler on
- Expo Router 58 (drawer is built into `expo-router/drawer`, no @react-navigation/drawer)
- Reanimated 4.7 + react-native-worklets (`scheduleOnRN`, not `runOnJS`)
- Gesture Handler 3.3: use the hook API (`usePanGesture`, etc.) with `GestureDetector`
- TanStack Query for ESPN data, AsyncStorage for the favorite team

## Conventions
- Routes in `src/app/` are one-line re-exports of a screen (`export { StandingsScreen as default } from '@/features/standings'`);
  layouts (`_layout.tsx`) stay there. Everything else lives in `src/features`, `src/components`, `src/hooks`, `src/lib`,
  `src/navigation`, `src/state`, `src/widgets`
- **One folder per component or screen**, named in PascalCase, holding everything that belongs to it:
  ```
  features/game/components/ShotChart/
    ShotChart.tsx          the component
    constants.ts           top-level constants it uses (add `use<Name>.ts`, `types.ts`, `<Name>.skeleton.tsx` the same way)
    ShotChart.stories.tsx  its Storybook stories (only if the stories are about this one component)
    index.ts               `export * from './ShotChart'`
  ```
- `features/<name>/` groups one area of the app: `components/` (its building blocks), `screens/` (one folder per screen),
  `stories/` (stories that span several of its components), `utils/` (helpers shared by its components), and an `index.ts` that exports
  `components` and `screens`. Features: `allstar around awards calendar compare cup draft events game home intro leaders news onboarding pickem player playoffs search standings team watchlist wire`
- `components/` is only for pieces used by several features: `Screen` (header, loading/error states), `Glass` (a surface drawn as iOS 26 Liquid Glass through `expo-glass-effect` and as a plain translucent view on older iOS or a build without the module; always the dark variant, for things that float over content: Rule of thumb: glass is for floating controls and for the selection, not for every resting item (each one is a native effect view), and it carries a faint white `FROST` tint by default because dark glass on the dark app reads as a hole. `Chip` (+ `ChipText`) is the one filter/mode chip (StickyBar periods, play-by-play filters, shot-chart players, game log stats, Cup and Bracket rounds, the League and Team Leaders stat rows in size `lg`): the chosen chip is glass (not `interactive`: the system's press effect grows the glass while it is held, which pushed the chosen chip out over its row's edge), optionally tinted with `color`, the rest a plain pill. The `Segmented` thumb, `SeasonButton`, `SearchInput` (`bare` when a screen draws the pill itself around an icon, as Search does, so no second glass box sits inside it), the drawer's search row and Mine/Change pills and the Calendar's `ViewSheet` are glass too. `GlassButton` is its round or pill-shaped button: the header's menu/back and `IconButton` circles, the game page's back and star, the player page's back, star and Compare in the team's tint; the Calendar's Today pill), `Segmented`, `Chip`, `Collapsible`, `Expandable`,
  `RollingNumber`, `LiveFlash`, `DataHealthBanner`, `SeasonPicker`, `SearchInput` (search field with a hand-drawn placeholder: iOS puts TextInput's own placeholder below the caret with a custom font), `Form` (W/L dots and chips), `HeadToHead`, `Icons`, `Basketball`, `NbaLogo`, `TeamMark`
- Import rule (ESLint enforces it): use a folder's index, never a file inside it. From outside a feature: `@/features/game`; shared UI:
  `@/components`; also `@/lib/espn`, `@/hooks`, `@/state`. Inside a feature: a sibling component is `../ShotChart`, a screen
  reaches the feature's components via `../../components`. A new component = new folder + add it to the feature's `components/index.ts`.
  A feature may use another feature only through its index (e.g. `team` uses `@/features/watchlist`); keep these acyclic.
- `lib/`: `espn/` (client, teams, schedule, standings, game, scoreboard, players, player-profile, team-stats, tagged), `game/`
  (game-model, quarter-stats, period-stats), `league/` (bracket, cup, team-stats, titles), `theme/` (colors + team marks), `widgets/` (widget props, snapshot builders, timeline, live-game: pure); `date.ts`
  and `data-health.ts` stay single files
- `navigation/` (`openDetail`, depth tracker), `widgets/` (iOS widgets and the Live Activity, one folder per widget like a component; its `index.ts` exports only `WidgetSync`, because the widget views import native modules and are loaded lazily by `WidgetSync/sync.ts`). Everything pure about widgets (props types, snapshot builders, the timeline, `live-game`) lives in `lib/widgets/` (`@/lib/widgets`), which Node tests can load
- Colors come from `teamTheme(team)` in `src/lib/theme`; don't hard-code team colors
- Pick logos with `logoOn(team, onColor)` so they read on dark or light backgrounds
- Fonts: `fonts.display` (Big Shoulders Display) for headlines and numbers, Barlow for body
- Animations run on the UI thread; avoid React state inside gesture or sensor callbacks
- No icon library is installed; icons are hand-drawn SVGs in `src/components/Icons`

## Design system
The look is dark, team-colored and scoreboard-like: Big Shoulders Display for numbers and headlines, Barlow for text, a dark page tinted by the selected team, `Liquid Glass` only on small floating controls. Everything lives in `src/lib/theme` (tokens, `teamTheme`) and `src/components` (primitives); `CLAUDE.md` is its documentation, Storybook (`npm run storybook`) is its picture.
- **Tokens** (`lib/theme`): `palette` (arena, chalk, muted, maple, and the meanings `win`, `loss`, `gold`: never write a green, red or gold hex, and `live` is the win green), `surfaces` (`faint` / `card` / `raised`: the translucent white layers cards, rows and fields are made of: never write `withAlpha('#FFFFFF', 0.0x)` for a background), `radius` (8 / 12 / 16 / 22 / pill), `space` (2 / 4 / 8 / 12 / 16 / 24 / 32), `fontSize`, `motion` (160 / 240 / 450 ms, easing `Easing.out(Easing.cubic)`) and `textStyle` (`sectionLabel`, `emptyTitle`, `emptyText`: spread into a style). They are the values the app already used most, so a screen moved onto them barely changes. The older screens still hold ad-hoc radii, font sizes and spacings (about 30 radii, 27 font sizes at the last count): move them onto the scales as you touch them, and use the scales for anything new. Widgets and the Live Activity run in their own runtime and cannot import the tokens: they repeat the hex values.
- **`teamTheme(team)`** is the only way to get a team's colors (`TEAM_PALETTE` in `lib/theme/theme.ts` replaces ESPN's pair for nine teams whose look was another team's: the Pistons, Knicks and 76ers were one royal blue, the Pacers, Nuggets and Pelicans one navy, the Nets and Spurs one black, the Lakers and Kings one purple, the Wizards one more red among Raptors, Bulls, Rockets and Hawks. Now: Pacers lemon gold with a navy stripe, Pelicans their navy a shade deeper than the Nuggets' (`#06182E`; a dirty gold was tried and did not suit their logo or jerseys, and a navy card cannot be 16 apart from the Nuggets', so it is only about 7 in Lab) with their red as the stripe and accent, which is what tells the two apart (`tests/theme.test.ts` checks the stripes and accents), Nuggets left on ESPN's own navy and gold (a bright blue and a deep royal blue were both tried and rejected), Knicks a deeper orange (a shade under their own, so white text reads on it, 3.1:1) with blue, Spurs silver with black, 76ers ESPN's own blue (the pair was left alone: it was the jersey blue the owner liked), Pistons a deep navy with red, Wizards a cornflower blue (`#6A82E6`, white text 3.5:1) with a red stripe (the deeper blues are taken by the 76ers, Pistons, Thunder, Mavericks, Timberwolves and Grizzlies, a vivid royal blue read as too much blue, and a pale silver-blue needed dark text), Kings a lighter violet, Hawks a scarlet (the Rockets' red was the Hawks' too) with their own gold, Raptors charcoal with their red as the accent (ESPN's red was the Bulls' to 3.9 in Lab, and the reds left no free slot; on that card they wear their own red logo, `COLOR_LOGO` in `lib/theme`, which `logoOn` honors, instead of the white one, and the player card's watermark of it is drawn at 0.22). The key is ESPN's lower-cased `color|alternateColor` pair, so it works for a team from any feed and a team whose ESPN colors change falls back to them; `teamColors(team)` gives the pair a team is drawn in and `matchupColors` uses it. The cards were picked to be at least 16 apart in CIE Lab from every other card, where ESPN's were 0 for three pairs and 3 to 11 for six more; the reds (Hawks, Bulls, Raptors, Rockets, Trail Blazers, Heat, Cavaliers) were left as they are on purpose, told apart by their accents and logos. Text on a card is near-black from a luminance of 0.30, where white falls under 3:1 (it was 0.45, which no card sat between until the Pacers and Knicks). `tests/theme.test.ts` keeps the groups apart and no two cards equal).  `primary` / `secondary` are ESPN's; `background` is the dark page; `onPrimary` the text on a card; `brand` the team's own bright color for FILLS and graphics (bars, washes, dots), which can be as dim as 2:1 on its own page; `accent` is `brand` lifted until it reads on the page at 4.5:1, for anything READ (numbers, labels, icons, the tab underline); `stripe` the card's stripe; `edge` the line along a team card that shows against both the card and the page (a black or navy team's card is within 1.2:1 of its page without one). `tests/theme.test.ts` holds these guarantees for all 30 teams (colors recorded in `tests/fixtures/team-colors.json`); `contrast()` and `ensureContrast()` are exported. Never read `team.color` directly.
- **Primitives** (`@/components`): `Card` (neutral `tone`, or `team={theme}` for a team-colored card with its edge), `Pill` (muted / gold / win / loss, or `on={theme.onPrimary}` frosted on a card), `Button` (primary / secondary / quiet), `SectionLabel`, `EmptyState` (`placement` top or center, optional icon and action), `Chip`, `Segmented`, `Glass` / `GlassButton`, `Skeleton`, `Screen` header, `Icons`, `Trophies`, `CardLights`. `MiniPlayerCard` and `MiniTeamCard` (small trading cards, the same height, with `MiniCardEmpty` for an empty seat: the key matchup, a finished game's duel and Compare, where the two players or teams sit side by side as cards with a VS badge between them, a seat to fill when one is missing, the players' numbers (season or career averages, the better of each pair lit), the teams' record and place; a card chosen after the screen has settled is dealt in with `dealIn` (it fades up and slides in from its own side, the second 100 ms after the first; flat on purpose: a card turning in perspective swung over the VS badge whatever its `zIndex`, 3D layers ignoring it), and its numbers are skeleton blocks until they arrive, never dashes; as the page scrolls the two cards thin out and shrink while the header's own title (`CompareHeaderTitle`, `features/compare/components/CompareBar`, the `title` node of the `ScreenHeader` beside the back button) turns from the word "Compare" into the two sides themselves, a small face for a player or a logo for a team and a short name each (a player's is his last name, suffix dropped (`lastNameOf` in `lib/league/header-names.ts`); the header is one group, face, name, VS, name, face, with the same gap between all of them, centered on the screen: each avatar right beside its name and the VS exactly halfway between the two names, so it moves with them; both names are the same size, full when the two last names fit together (`namesScale`: at most 20 letters, so a long name beside a short one still fits: Antetokounmpo and James), otherwise both smaller by the same factor down to half (Wembanyama and Antetokounmpo 0.87, Gilgeous-Alexander and Alexander-Walker 0.59) and nothing is cut; the avatars pinned to the row's ends with the names truncated, first names, and a size per name were all tried and looked uneven; a team's is its three-letter NBA code, `tricode` in `lib/espn/common.ts`: ESPN's GS, NO, NY, SA, UTAH and WSH read GSW, NOP, NYK, SAS, UTA and WAS) with VS between, centered on the screen (VS at its middle, the two avatars fixed at the row's two ends so they are always the same distance apart whatever the names, the names between them pushed up against the VS: face, name, VS, name, face (for teams the logos sit right beside their codes instead, which are all three letters wide)) and rising into that same row from below as the word goes, driven by the scroll (`scrollY`, `useSlotsStyle`; thresholds are worked out outside the worklets: a plain function called inside `useAnimatedStyle` crashed it), so the page never loses who is being compared (the player page's top bar does the same for one player); `useTeamPicks` gives the page and `TeamCompare` the same two teams. Under the radar and the rows, the player comparison has a **head to head** (`PlayerHeadToHead`): the games in which the two played for opposite teams over the last three seasons, regular season and playoffs, newest first (`playerHeadToHead` in `lib/league/player-h2h.ts`, pure and tested: the same game id in both players' game logs with a different opponent in each, the same opponent meaning they were teammates; each player's team that night is the other's `opponent`; `usePlayerSeasonLogs`, `fetchPlayerGameLog(id, season)` reads `gamelog?season=`, a finished season cached for good), the latest five with each player's points, rebounds and assists and the game's score, the higher scorer lit, each row a tap that opens the game, over a line with who won more (by the game's score) and what each averaged; "They have not played against each other in the last three seasons" when there are none. The same player (or team) cannot be in both seats: the picker shows the other seat's player dimmed as "Already picked", and a link asking for the same twice leaves the second seat empty. The team card on the team page shows skeleton blocks for its record and place too while they load), `LogoWatermark`, `EdgeFade`. Reach for one of these before writing another rounded translucent box, "Try again" button, uppercase label or empty state.
- **Seeing it**: Storybook "Foundations / Team theme board" (all 30 teams: card with and without edge, accent before and after with the ratio, stripe), "Foundations / Primitives and scales", "Foundations / Theme".
- **Accessibility**: Reanimated animations follow the system's Reduce Motion (stated in `_layout.tsx` with `ReducedMotionConfig`; the explicit `useReducedMotion` checks are for what Reanimated cannot see: the gyroscope tilt, the intro, skeleton pulses). Text is not capped for Dynamic Type (React 19 dropped `defaultProps`, so a global cap would need a themed `Text`): cards and pills have fixed heights, and larger text sizes are untested. The app is dark-only on purpose (`userInterfaceStyle: dark`).

## Data
ESPN endpoints are undocumented and may change. All parsing lives in
`src/lib/espn.ts`. If a field shows "–" in the UI, inspect the live response
and fix the normalizer there rather than in components.

Per-quarter and per-half player/team stats are not in ESPN's box score. `src/lib/game/quarter-stats.ts`
rebuilds them from the play-by-play feed (`Play[]` from `fetchGameSummary`), and it also powers the
win-probability chart and play-by-play tab. Check accuracy against a game with
`node --experimental-strip-types --import ./tests/register.mjs scripts/validate-quarter-stats.ts <gameId>`; counting stats match
the box score, derived plus-minus can drift by ±1.

Other data sources beyond the main ESPN site API: the common/v3 `gamelog` endpoint (player game log) and `search/v2` (player search, used by Search and Compare: it knows retired players like Garnett, Nowitzki and Gasol, which `common/v3/search` does not, and it lists every sport and league at once, so `normalizePlayerSearch` keeps the rows whose uid is NBA (`l:46`) and that have an `image` (ESPN has no photo of the unknowns: obscure old players, two-way signings who never played) from a 50-row page; it names the team but has no id, so `usePlayerSearch` matches the name against the cached team list and a retired player's defunct club just has no team) and core-API team statistics (home screen team season card).
Team ranks (home card, Compare > Teams) are computed in `src/lib/team-stats.ts` from the one-call
`statistics/byteam` feed (`fetchLeagueTeamStats`); ESPN's own per-team `rank` fields are unreliable for
derived stats like 3P%. Player career tables come from the common/v3 athlete `stats` endpoint.
Scoreboards are keyed by US Eastern date (`toNbaDateKey()`), but days on screen are the device's own: `useGamesOnDay(day, today)` reads the one or two scoreboards that hold a local day (`scoreboardKeysFor`) and keeps the games that start on it (`startsOnDay`); on today a game that is on right now is listed too, even if it started the evening before. The Calendar day pages, Month cells, home scores strip and "today" (`localToday()`) all use it. Only the Live Activity and the widgets still think in Eastern dates (the Activity reads both today's and yesterday's board).
Worklet gotcha: never call plain JS helpers (e.g. `withAlpha`) inside `useAnimatedStyle`, and don't use
object spread in gesture hook configs; neither shows up in `tsc`, both crash at runtime.
React Query's cache is persisted to AsyncStorage for slow-changing keys only (see `PERSISTED` in `src/app/_layout.tsx`).

## Pregame, form and head-to-head
The Pregame section has a **key matchup** (`features/game/components/KeyMatchup`, right after who is favored) only when the game has a real one: `pickKeyMatchup` (`lib/league/key-matchup.ts`, pure and tested) needs two players of the SAME position (guards, forwards or centers: `positionGroup`), each among his team's best three by ESPN's rating once the injured are out (`MATCHUP_RANKS`) and each a star by the numbers (`isMatchupStar`: 20 or more points a game, `MATCHUP_MIN_PPG`, or, under 20, points, rebounds and assists together adding up to 28 or more, `MATCHUP_MIN_COMBINED`: 15 + 6 + 7 counts, 18.6 + 1.8 + 2.3 does not; the 28 is the rule that does the work, an 18-point bar let a role player through), so it is two stars across from each other; most games have none and show nothing (a role player across from a star, or two scorers of different positions, were tried and looked odd). They are two small trading cards (`MiniPlayerCard` in `@/components`: team color, `LogoWatermark`, position and a DTD flag, his photo melting into the footer, his number, name and PPG / RPG / APG, the higher number of each pair lit and the other dimmed) face to face, the title naming the position ("Key matchup · Forwards"). Of the qualifying pairs the one whose two places in the rankings add up lowest wins, ties to the pair with the bigger combined line (`fetchTeamRated`: the team's `rating` leaders list, best first; only those with a star's line get their athlete record read, for position and number, so for most teams the whole read is one request; `useTeamRated`); a player ruled out by the game's injury report (`info.injuries`, status Out) is never shown, a day-to-day one is, flagged. On mount the cards fly in from the sides and meet under a spring that settles without overshooting (an overshoot made them cross each other for a moment), with a white flash and the VS badge popping at the meeting (`meet` shared value; static under Reduce Motion). A tap on a card opens the player; "Compare their season" opens `/matchup-compare` with both players (`id`, `name`, `teamId`, `teamAbbr` and `id2`, `name2`, `teamId2`, `teamAbbr2`). Nothing is drawn while the two lists load, not a skeleton: most games have no matchup, so a placeholder would flash on every one of them. When a matchup does turn up after the page is up, the section fades in and what is below it (`Pregame`'s other blocks, `layout={GLIDE}`, a `LinearTransition`) glides down instead of jumping. `EdgeFade` (the photo's fade into the card color) lives in `@/components` for both cards. Tests: `tests/key-matchup.test.ts`; stories: "Game/Key matchup".
A finished game has its own **duel** (`features/game/components/GameDuel`, on the Summary tab right under the game leaders, whole game only): `pickGameDuel` (`lib/game/duel.ts`, pure and tested) looks for one player from each team who matched the other over the game, with no regard to position: both scored `DUEL_MIN_POINTS` (30) or more and within `DUEL_MAX_GAP` (6) points of each other (a "Scoring duel · 35 vs 32"), else both put up `DUEL_MIN_COMBINED` (40) or more in points, rebounds and assists together within the same gap of each other (an "All-round duel", 20 + 10 + 10 against 22 + 10 + 8); a scoring duel comes first, and among pairs the one whose lesser player did more wins. It is the same pair of `MiniPlayerCard`s and the same entrance as the key matchup (`KeyMatchupView` with `unit="game"`, so they show PTS / REB / AST of that game, and `section` for the game tabs' 14 pt rhythm), nothing when the game had none. Tests: `tests/duel.test.ts`.
`normalizeGameSummary` returns `pregame` (`winProb` from ESPN's matchup predictor, `odds` from `pickcenter` when a book has posted a line,
`form` = last five results per team from `lastFiveGames`). Odds are US moneylines converted to decimal (`moneylineToDecimal`); many games
have no line yet, so every part is optional and the card hides what's missing. There is no head-to-head feed: `fetchHeadToHead` reads one
team's regular-season and playoff schedules season by season until it has 10 finished meetings (`summarizeHeadToHead` in `lib/league`).
The Summary tab shows odds, form and head-to-head before tip-off; Compare > Teams shows head-to-head too.
All-Star selections are not in ESPN's awards (only the All-Star MVP): `fetchAllStars` reads each All-Star Game's roster from its scoreboard day (2003 on, dates in `lib/espn/all-star.ts`, add the new February each year) and `HonorsCard` shows them as "NBA All-Star". The playoff bracket is one tree (East above West, Finals as the last column, `BracketSection.byConference`); the play-in is a per-conference bracket (7v8 and 9v10 feed the 8th seed game).
What a game links to depends on its kind (`GameSummary.kind`, from ESPN's `header.gameNote` and `header.season.type` by `classifyGame` in `lib/espn/common.ts`; `season` is `header.season.year`) and is decided by `MatchupPlace` (game feature): regular season, the standings as below; playoffs, the pushed `/matchup-playoffs` (the bracket of that season, opened on the round of the series, both teams' series card lit); play-in, the same route on its Play-In pane; Cup group play or knockout (the Cup final too: it is in no standings), the pushed `/matchup-cup` on the groups (the group of the two teams first, their rows lit) or the knockout bracket; All-Star and preseason games, no link (they are in no table), and a playoff game before 2002-03 none either (ESPN's schedules have gaps there, the bracket cannot be rebuilt). These pushed screens are `PlayoffsScreen` / `CupScreen` with `pushed`, locked to the game's season (no season picker), and the lit teams travel as `Spotlight` (`@/components`, a context read by `SeriesCard`, `MiniSeries`, `GroupCard`, `Bracket`). A playoff game is marked like a Cup game: `PlayoffBadge` (playoffs feature; `playoffTag` in `lib/league/bracket.ts`: "WCF · G2", "R1 · G3", "FINALS · G4", "PLAY-IN") on the Calendar's `GameCard` and Agenda, and the same tag after the matchup in the game page's top bar (`GameTopBar` `tag`, "NBA CUP" for the Cup). In a playoff game each team's seed shows as "(3)" after its abbreviation (game card and game header; `usePlayoffSeeds`, from the season's playoff games through `playoffSeeds`, so the 7 and 8 seeds from the play-in are right; ESPN publishes no seed, and the hook shares the `postseason` cache and is persisted) and the series sits under the status ("ORL leads 3-2", "NYK won 4-2", "Tied 3-3": `seriesLine` over `competitions[].series.summary` on the scoreboard and the playoff entry of `header.competitions[0].series` on the summary; ESPN's text is the series as it stood after that game, so a finished game shows its own result and one still to come shows the present state). The Bracket opens on the drawn tree, scrolled to the game's series, when it was opened from a game (`Spotlight`). Every game links to Standings (`openStandings(teamIds, date)` in the game feature): the screen reads `teams` (comma separated ids, highlighted in matchup colors, opens the shared conference or the league table and scrolls to them) and `season` params. Before tip-off the Summary tab shows the standings card (same conference: that table with both rows lit; different: each team's place).
The drawer (`components/DrawerMenu`) has twelve rows and a search entry on top (opens `/search`), in two groups. What is yours (no heading): Team card, Calendar, Watchlist (the players and games you starred) and Pick'em. League: Standings, Playoffs, Player leaders, Team leaders (teams ranked by a team stat), Teams (all 30 teams' rosters in a pager; the drawer search finds teams too), Compare (players or teams), **Around the league** (`features/around`: one pager of three panes, News, Injuries and Moves, with `PaneTitle` and a dot per pane like the Playoffs screen, `pane` param; it is the old News screen and the old League Wire in one: News = ESPN's feed with its chip strip, Injuries and Moves = the wire's two panes) and **Events** (`features/events`: a hub of four cards, NBA Cup, All-Star Weekend, NBA Draft and Awards, the ones that are on now first and tagged "On now" (`eventsOnNow` / `orderEvents` in `lib/league/events.ts`, pure and tested, by calendar month); each card opens its own drawer screen, and the Events row is lit on any of them, `also` in `MenuItem`). Merging was tried further and undone: Watchlist with Pick'em ("My games", a misleading name since players are starred there too) and Player with Team leaders (two stacked switchers, the Players / Teams one over the stat pills, looked bad) were each one screen with a `Segmented`, and the user wanted them separate; Playoffs was in the Events hub and is a row of League again (it is the season itself, like Standings, not a yearly event; putting it inside Standings would again be a switcher above a switcher). Only things of one kind were merged (the news and the wire are both "what is going on"; the four events are both rare and yearly). **A drawer route must be declared with a `Drawer.Screen` in `(drawer)/_layout.tsx` to open from a link**: a file without one is ignored by a deep link (it landed on the Team card, with no error), which is why `news` and `wire`, which stopped being menu rows (they are panes of Around the league), are still declared and render the pager on their pane (`<AroundScreen pane="injuries" />`); a `Redirect` from such a route did not work either (it ended on the Team card), so they render instead. Preloading builds the Calendar, Team Leaders and Teams, and Player Leaders later. Team card and Calendar are the two main screens: a Calendar button sits beside the menu on the Team card (`ScreenHeader`'s `afterMenu`); the Calendar has no button back, the menu is its way out; `SceneFrame` also settles each screen in when you reach it (content eases from 22pt right to rest over 520 ms with an ease-out quint curve, no scale, and the fade is a veil in the menu color over the screen, not the screen's own opacity (that forced an offscreen render of every card per frame), started two animation frames after the screen's first draw so a heavy first render does not eat the start of the move; the first screen after launch skips it, the intro hands over, and it plays for every deliberate trip to a drawer screen (menu or any button, plain `router.navigate`), but not when a game, player or team page on top of it closes and the same screen shows again (`returningFromDetail` in `@/navigation`, with `lastScene` in `SceneFrame` so a button on a detail page that goes to a different screen still slides): returning to a screen from a game or player page also focuses it, and sliding it in then looked like the menu dragging open; opacity never starts at 0 or the menu's color would show), `SceneFrame`, wired through the drawer's `screenLayout` (a module-level function: an inline one rebuilds every screen), draws corners, shadow and edge on top of each screen while the menu is open, without clipping the screen (clipping made opening screens lag). Standings opened from a game is the pushed `/matchup-standings` route, so back returns to the game. Compare opened from a player page or a team page is likewise the pushed `/matchup-compare` route (`CompareScreen pushed`, back arrow in the header; the drawer's own Compare keeps the menu button). The drawer's edge swipe is only on while a drawer screen is on top (`swipeEnabled` from `useSegments()[0] === '(drawer)'` in `(drawer)/_layout.tsx`): a game, player or team page opened over it leaves the drawer mounted underneath, whose edge swipe would otherwise catch the back swipe and drag the screen below open like the menu. A new screen = a route file, a `Drawer.Screen`, and an entry in `SECTIONS` (or a card of the Events hub).
The Teams screen (`RosterScreen`, route `(drawer)/teams`; `/roster` redirects to it) is a horizontal pager with one page per team (`TeamRoster`), alphabetical, opening on the team you are viewing. Its position is a fractional `page` shared value: the screen background (the team's color, header included), the `TeamPills` strip with its team-colored outline and the strip's own scroll all follow it. Performance rules: only five pages are mounted (`windowSize={5}`); a move of more than two teams jumps the pager in one step while `page` is animated separately (`jumping`), instead of scrolling through pages; rows are built only for the page last settled on and its neighbours, every other page shows the static `RosterSkeleton` (no pulsing skeletons: dozens of animated views per page); once at rest, rosters and first headshots of the teams two swipes either way are prefetched into the React Query cache. Swiping does not change the app's selected team; a tap on the team banner at the top of a page does (`viewTeam`, then `/home`): the banner says "Team page" and is the way from a roster to that team's card.

A player on the league injury report (`useInjuries`, the Wire screen's cached read) gets a red cross pill "OUT" (gold "DTD" when day-to-day) at the far end of his tags row, on a dark base so it reads on every team color (`injury` prop, `InjuryIcon`). The profile (honors) and the career (titles, Cups) are read as the page opens, not after it settles, so the trophies are not late (they are cached and persisted); each fades in when it arrives. The five award trophies (`components/Trophies`: `MvpTrophyIcon` a ball on a column, `FinalsMvpTrophyIcon` a ball in a hand, `ConferenceMvpTrophyIcon` a ball in a ring, `DpoyTrophyIcon` a raised hand, `RoyTrophyIcon` a star) are drawn on the same 24 x 30 canvas as `LarryOBrienIcon`; they are approximations (real trophy photos were considered and not used: copyrighted designs, not tintable, and they do not read on every card), and the Honors card uses them too. ## Pick'em
Call the winner of an upcoming game before tip-off and the app keeps score (`features/pickem`, route `(drawer)/pickem.tsx`, drawer "Pick'em" with `PickemIcon`, in the group that is yours). Everything is on the phone: there is no backend, so no "what fans picked" (a made-up number would break the real-numbers rule). Logic is pure and tested in `lib/league/pickem.ts` (`tests/pickem.test.ts`): `isLocked` (a pick is open until tip-off; an unreadable date counts as locked), `favoriteOf` (ESPN's win chance, else the book's favorite flag, else the shorter price, else nobody), `winnerFromScores`, `settlePicks`, `awaitingResult` (a pick waits for its game 3.5 hours after the start), `summarizePicks` (record, accuracy, the run you are on, best run, `versus` = how you did against always taking the favorite over the settled games that had one, upsets called). Only `isPickableKind` games count (regular season, playoffs, play-in, Cup; not All-Star or preseason). The store is `state/pickem-store.tsx`, a small external store like the team's (one pick per game id, `AsyncStorage` key `courtside:pickem`; `usePick(gameId)` wakes only that game's card, `usePicks()` the screen; `setPick` toggles: the same side again takes the pick back; `setPickFavorite` fills the favorite in for a pick made from a list, which carries no odds: `PickButtons` reads the game's own summary through the shared `['game', id]` query after the tap). `PickemSync` (mounted in the root layout) hydrates the store and writes winners onto the picks whose games are over, from the same scoreboard query the Calendar reads (one call per Eastern day with a waiting pick; when the app opens, returns to the foreground or a pick is made); `PickCard` also settles from the game's own score when its page opens. UI: `PickButtons` (two big tiles, each just a team's logo on its matchup color, no text: the win chance is in the card above, so the buttons do not repeat it or the "Favorite" tag; the chosen one is stronger with an edge and a tick, green when right, red with a cross when wrong; locked at tip-off by one timer in `useLocked`, not polling; `size` lg 104 pt on the game page, sm 68 pt in the list), `PickCard` ("Who will win?" right under the odds in the Pregame, and at the top of the Summary tab of a game that has started when you picked it, with how it went), `PickBadge` (a tag on the Calendar's `GameCard`: "PICK NYK", then a tick or a cross), `PickRecord` (the score card), `PickRow`, and `PickemScreen` (the score card, today's and tomorrow's games with buttons, picks waiting for a result, history). Stories: "Pick'em/Score card".

## Old team names
ESPN keeps one team id per franchise (the Sonics and the Thunder are 25, the New Jersey and Brooklyn Nets 17, the Vancouver and Memphis Grizzlies 29, the Bullets and Wizards 27, the Bobcats and today's Hornets 30, and 3 is the Pelicans with the original Charlotte Hornets, New Orleans Hornets and New Orleans/Oklahoma City Hornets before them: ESPN files the Hornets' first 14 years there, though the NBA gave that history back to Charlotte in 2014) and, in the core API, a season-scoped team record (`sports.core.api.espn.com/v2/sports/basketball/leagues/nba/seasons/{year}/teams/{id}`) with the name, tri-code, logos and colors of that season (a season is the year it ends in: 2009 is 2008-09; records begin in the 1980s, 21 teams in 1980). **ESPN has names, not old logos**: the `guid/.../logos/default.png` it files under a retired name (the SuperSonics, the New Jersey Nets) is today's emblem of the franchise (the OKC shield, the Brooklyn B; checked by opening the files), and no `.../sea.png` or `nj.png` exists. So the app carries five old logos itself (`assets/images/history-team-logos`, 400 px, sportslogos.net's artwork, downloaded on the user's say-so: a practice app, not for distribution): the 2001-08 SuperSonics (`25|Seattle SuperSonics`; from Wikipedia's `Seattle_SuperSonics_logo.svg` rendered at 500 px, because sportslogos.net's GIF of it has a baked-in white background), the 1998-2012 New Jersey Nets (`17|New Jersey Nets`), the 2007-12 Charlotte Bobcats (`30|Charlotte Bobcats`) and the 2008-13 New Orleans Hornets (`3|New Orleans Hornets` and `3|New Orleans/Oklahoma City Hornets`) and the original Charlotte Hornets, 1988-2002 (`3|Charlotte Hornets`: the teal hornet, so the early seasons of the Pelicans' id show Charlotte, not a pelican). One picture per name, though a name often wore two or three designs; a name with no picture (the Bullets, the Vancouver Grizzlies, the San Diego Clippers, the Kansas City Kings) keeps today's logo. `installEraLogos()` (`components/EraLogos`, called at module scope in the root layout) resolves the files and hands their URIs to `registerEraLogos` in `lib/espn/franchise.ts`, keyed by team id and era name, because only the app can `require` an image and the Node tests load that module; `eraLogoFor(teamId, season)` gives the picture for a season when the team had another name then, and `withEraLogo(team, season)` swaps it into a feed's team. To add one: put the PNG in that folder, add its line to `LOGOS`. The persisted feeds hold the pictures' addresses (a release build's bundle path changes with every install), so `installEraLogos()` returns a fingerprint of those addresses and the root layout's cache buster is `v12-<fingerprint>`: a cache written for another install, or before a file was replaced, is dropped. **The scoreboard, standings, schedule-opponent and game-summary feeds already carry the era's name and code** (a 2005 scoreboard says New Jersey Nets, NJ), so the app puts only the old logo in their place (`eraLogoFor` in the scoreboard, schedule-opponent, standings, game-summary, player game-log and career normalizers, by the game's or season's year); what lost the name was the app looking a team up by id in today's team list. `lib/espn/franchise-eras.ts` is the table of eras, generated by `node --experimental-strip-types scripts/build-franchise-eras.ts src/lib/espn/franchise-eras.ts` (about 15 s for 47 seasons; rerun it when a team changes its name): a new era starts where the name changes (a new logo or color alone is ESPN re-skinning; "LA" and "Los Angeles" count as one name because ESPN switches the Clippers in 2002). `lib/espn/franchise.ts` (`tests/franchise.test.ts`): `teamEras(id)`, `eraIn(id, season)`, `renamedSince` and `teamInSeason(team, season)`, which returns the team with that season's name, location, nickname and tri-code (ESPN's own, the one its feeds print: NJ, NO; only the pre-1985 San Diego Clippers and Kansas City Kings, which ESPN has no code for, get SDC and KCK), the era's logo where there is one, **today's colors** (so the theme does not change), and the very same object when the team was called then what it is called now (and the same derived object each call, so memos hold). It is used where a past season looks a team up by id in today's list: the Draft (`teamOf` with the draft's year: the Sonics drafted Westbrook, so the row says SEA with the Sonics logo), Awards (the winner's team that season), the Calendar (`GameCard` and `opponentLook` for the Month and Agenda, by the game's date) and `fetchTaggedGames` (the playoff and play-in sides of the team whose schedule is read, so a past bracket says SuperSonics). Standings and the game page needed only the logo. **A team's card in any past season** (`TeamSeasonHome`, `features/team`): `/team/<id>?season=<year>` for a season before the current one shows the same `TeamCard` as the team page in that season's name and logo, and, where the team went by a name with an entry in `ERA_COLORS` in `lib/espn/franchise.ts` that season (the SuperSonics, the New Jersey Nets, the Charlotte Bobcats, the first Charlotte Hornets, the New Orleans Hornets), in that name's colors; any other team is drawn in today's colors (`teamAsItWas`: `teamInSeason` plus the era's colors, which come from the logos and were picked so the logo stands out from its own card: a silver card for the navy Nets, a purple one for the teal Hornets, a deep navy for the Bobcats), the season's record and place (from that season's standings), home and away of the regular season (the first `wins + losses` games, since the playoffs follow it and before 2003-04 ESPN gives them no note), the win percentage, **how the season ended** (`SeasonResultCard`, from `seasonResult` in `lib/league/season-result.ts`, pure and tested: "Missed the playoffs", "Lost in the play-in", "Lost in the first / second round", "Lost in the conference finals", "Lost in the NBA Finals" or gold "NBA champions" with the trophy; only from 2002-03 on, ESPN's older schedules have gaps), **the season's best player** (`TeamStarCard` with a `season`: ESPN's `seasons/{year}/types/2/teams/{id}/leaders` `rating`, the same feed as the team page's, kept for good), a "Today" row that opens the franchise's present page, and every game of the season (a tap opens it; playoff games carry their tag). ## Awards and Game Score
- **Awards** (`features/awards`, route `(drawer)/awards.tsx`, a card of the Events hub, `MedalIcon`): a season button in the header (`SeasonButton` + `SeasonSheet`, as on Playoffs and the Cup, offering the seasons of `awardSeasons()`) over one season, from 1999-00 (`AWARDS_FROM` 2000; ESPN has them back to 1980 and the older years were left out on purpose) (`awardSeasons()`: the latest is the season that finished, or the current one from April, when its awards are being given), `AwardsHero` (the years and the MVP; the champions are deliberately not here, the Playoffs and Cup screens show them) and one `AwardSection` per group (Season awards, Playoffs = Finals and conference finals MVPs, More awards, All-NBA, All-Defensive, All-Rookie, NBA Cup); an award with one winner is a row of a shared card (`WinnerRow`), an award with five (a team) a card of its own in court order. Data is `fetchSeasonAwards(season)` in `lib/espn/awards.ts` (`useSeasonAwards`, persisted under `seasonAwards`, a finished season never changes): the season's `awards` list, each award's record, then each winner's athlete record (about fifty requests, all at once). **ESPN holds only the winners**: no voting, no runner-up, so there is no "top 3" of a past season (the sportsbook's odds are the only favorites, in League Leaders "ODDS"); the `note` on a winner is junk ("Test Note"). A winner's team is the franchise's ESPN id, shown as it was called that season (a 1996 Sonics winner says Seattle, as on the Draft screen), and the position ESPN gives is today's record's ("NA" for the early years), used only to put a team of five in court order. Tests: `tests/awards.test.ts` over trimmed real 2025, 1996 and 1980 records; stories: "Awards".
- **Courtside Rating** (`lib/game/game-score.ts`, the `CR` column of the box score; the legend sheet says "CR - Courtside Rating"): ESPN publishes no per-game player rating, only the box score, so the rating is the app's own: Hollinger's Game Score (`PTS + 0.4 FGM - 0.7 FGA - 0.4 (FTA - FTM) + 0.7 OREB + 0.3 DREB + STL + 0.7 AST + 0.7 BLK - 0.4 PF - TOV`, raw: 10 is an average game, 20+ very good) turned into a 1-10 rating by `ratingOf`, a straight line between `RATING_POINTS` (raw 0 is a 5, 10 a 7, 16 an 8, 25 a 9, 38 a 10: a 40-10-10 game on good shooting): so 5 is already bad, 6-8 is the range of a typical rotation player, 8+ very good, 9+ elite. For the whole game only (the column is hidden under a period filter, where a quarter cannot be put on that scale), and not for a player under `MIN_RATED_MINUTES`. **While a game is on the rating is a projection of the final one** (`projectedRating` in `game-score.ts`): the raw Game Score is a count, so a young game would rate everyone low. It is the score so far plus what he can be expected to add in the rest of the game, `rate * (min(40, minutes / fraction) - minutes)`, the rate leaned toward a typical player's (`PRIOR_RATE` a third of a point a minute, `PRIOR_MINUTES` 8) while he has played little; `fraction` is the minutes both teams have played over 240 (`gameFraction`: a live box score has no clock), and at 1 it is exactly the finished rating. `useLiveRatings` (`BoxScoreTab`) takes the ratings when the tab opens and again once four more minutes of the game have been played (REFRESH_TEAM_MINUTES 40, about three or four times a quarter), never on a play: they stand still between refreshes and a note under the view switch and the legend say they are projected (5: garbage time reads as a bad game). It is drawn as a solid square in the color of its band (`ratingTone` in `lib/theme/tokens.ts`, from the rating as shown to one decimal): under 6 red, 6-7 orange, 7-8 green, 8-9 light blue, 9+ solid blue (the user's own list), the number white on every band (a 10 is written "10", not "10.0"), sharp corners (`RatingSquare`: 26 pt in the detailed view, 30 in the default one); a player with none shows a dash. Retune `RATING_POINTS` if the user finds it too kind or too harsh. The box score opens sorted by points, highest first, and the column you chose stays chosen when the period filter changes (only the rating, which a period does not have, falls back to points until the whole game is back; among equals the one with more minutes comes first, which puts who played in a quarter above who did not); a tap on a column header sorts by it. Tests in `tests/game.test.ts` and `tests/theme.test.ts`.
- **Box score views** (`features/game/components/BoxScoreTab`, `LegendSheet`): a "Detailed view" switch over the table (off at first, not remembered). The **default view** (`SimpleTable`) is a bigger row per player, 48 pt photo with a gold "Starter" tag over its bottom edge (plus the gold edge on the row), name and "jersey position" under it written out ("7 Forward", `positionName` in `lib/game/position.ts`; the detailed view keeps "7 F"), rows 58 pt high, and four columns that fit with no sideways scroll: CR (only for a finished game), PTS, REB, AST, and a TEAM totals row. The **detailed view** (`DetailedTable`) is the old table, every stat column, with the player column (photo, name, jersey and position, the CR square) pinned: `DETAIL_COL_FULL` 192 pt at rest, shrinking to `DETAIL_COL_SHRUNK` 150 over the first `DETAIL_SHRINK_AT` 56 pt (`detailColWidths`: without the rating, under a period filter, both are `RATING_BOX` + 8 narrower, so no room is kept for a square that is not there) of the stats' scroll (an animated `width` from `scrollX`: the name is cut short, the rating stays beside it), a soft shadow on the pinned edge and a thin `ScrollIndicator` under the column names (a track and a thumb; the visible width is worked out from the table's width and the same shrinking curve, nothing is measured while scrolling; hidden when everything fits). Both tables sort by a tap on a column name (`SortHeader`, the arrow hugs the name; default points, a period filter minutes; switching to the default view drops a sort by a column it does not have) and carry a "Legend ⓘ" button (`LegendButton`) in the header's corner that opens `LegendSheet`, a bottom sheet animated like the Calendar's view sheet: what every column stands for, the rating's note and its color bands, and the Starter tag. The old "tap a column to sort / gold edge" line is gone; only a period filter still prints a note ("stats rebuilt from play-by-play").

## Odds, League Wire, power index and the team page
- **Odds** (`lib/espn/futures.ts`, `useFutures(withAthletes)`): ESPN's futures feed is one sportsbook's (DraftKings') American moneylines for the title, each conference, MVP, ROY, DPOY, Sixth Man, Most Improved, Clutch and Coach of the Year. A "chance" is the line's implied probability scaled so a market adds up to 100% (the margin removed); it is the book's opinion, never ESPN's, and the UI says so. The team page's `TitleOdds` card (title, conference, "Nth favorite") asks for the team markets only (`withAthletes` false), and so does the Team Leaders "Odds" page (`OddsPage`: all thirty teams' title chance, favorite first, with the conference chance); the League Leaders "ODDS" tab (`AwardOdds`, the player awards only: the title odds moved out of it; it lists what ESPN's feed holds, which early in a season is the MVP market alone, the others (Rookie, Defensive Player, Most Improved, Sixth Man, Clutch, Coach) appearing as the sportsbook opens them, and the page says so) asks for the award markets too, whose favorites' names, photos and teams are one record request each (about forty), which is why the two are separate queries. A coach's id is not a player's: no photo, no page. Hidden when a team is not in a market (no markets in the offseason).
- **League Wire** (`features/wire`, now the Injuries and Moves panes of Around the league; `/wire` still opens the injuries): a sideways pager like the Playoffs screen, no switcher: the title is `PaneTitle` (`@/components`, moved there from the playoffs feature since two screens use it: the pane names cross-fade with the pager's fractional position, a dot per pane), the panes not on screen are a skeleton until the screen has settled or they are swiped to; `lib/espn/wire.ts`, ESPN's league-wide `injuries` (every team's report, about 90 players in season: status Out / Day-To-Day, what and where, expected return, ESPN's one-line note) and `transactions` (the season's moves, newest first; `?limit=` is the page size, 40 more per "Show earlier moves"). Injuries are grouped by team (a count beside each, the favorite team first) with an All / Out / Day-to-day filter that carries its counts; a row is two lines (name and position with the status pill, what is wrong with the expected return date) behind a bar in the status color (red out, gold day-to-day) so a screenful scans before it is read; ESPN's one-line note repeated the same facts and is only the fallback when there is no detail; a tap opens the player. Tests: `tests/wire.test.ts`.
- **Power index (BPI)** (`lib/espn/power-index.ts`, `usePowerIndex`): ESPN's Basketball Power Index, the points a team would beat an average team by on a neutral court (`bpi`, split into offense and defense) with ESPN's own projection (final record, playoff / Finals / title chances in percent; `?limit=30` for all thirty teams). It is the first page of the Team Leaders pager (`BpiPage`, key `bpi`; `PAGES` in `TeamLeadersScreen`), followed by the sportsbook's title odds (`OddsPage`, key `odds`) and one page per team stat.
- **Team page order** (`TeamHome`), top down by what matters most now: team card (with a streak bubble, "W5" in green or "L9" in red on a dark pill at the end of the record row, bottom right, the top being clear for the logo, from the finished games: `streakOf` in `lib/widgets`), catch-up (own team), Home / Away / Arena, next game and form, season series against your team (a rival's page only), today's scores, the Cup standing (only while `cupIsOn`): the "on now" zone; then the team itself: the season numbers with league ranks (`TeamSeasonStats`, right after the "on now" zone: it sat below the recent games and the clips, far from the card it describes), `TeamStarCard` (the team's best player by ESPN's rating with PPG / RPG / APG, the same feed as the Team form widget; it sat between the next game and today's scores, which made the top of the page crowded and split the time-bound blocks), the last five results with a "Full schedule" link to the Calendar (it was eight: the list pushed everything else down), the clips, the odds, the watchlist (only when one of the team's players is starred), the roster button. Everything below the card is built in a second, interruptible pass.
- **Loading on demand**: drawer screens mount on first visit (React Navigation's default `lazy`), pager pages outside `windowSize` do not mount and so do not fetch, and the heavy reads are gated: the Cup (all thirty team schedules) is read on the team page only while the team's own schedule says it is on (`cupIsOn`, before it ran on every team page open all year), the odds' forty athlete records only where the names are shown, a drafted player's NBA id only for the rows on screen (`useDrafteeIdentity`), the clips and All-Star list after the page settles. Native bundles are not split by route (Expo's async routes and bundle splitting are web only), Hermes maps its bytecode lazily, and `inlineRequires` is off in Expo's Metro default (`@expo/metro-config`); turning it on was not tried: Expo's docs say nothing of it, and it can reorder module side effects (Reanimated, worklets, gesture handler) and could not be measured here.

## Player photos
ESPN has no headshot for many players from before the 2000s (Jordan, Iverson, Magic, Bird: the file is a 404), and Search used to drop anyone without one. `lib/espn/legend-photos.ts` holds `LEGEND_PHOTOS`, ESPN athlete id to NBA.com person id for the 84 retired players found with no ESPN photo and a real one on `cdn.nba.com/headshots` (NBA.com serves a silhouette placeholder for any id it has no photo of, so a blind fallback would put silhouettes on the unknowns: the list was built by matching names between ESPN's search and NBA.com's player index at `stats.nba.com/js/data/ptsd/stats_ptsd.js` and keeping a player only when the NBA.com file is not the placeholder, 12430 bytes at 1040x760, 4937 at 260x190). Every headshot URL goes through `headshotUrl(id)` (legend first, then ESPN's file) and `normalizePlayerSearch` keeps a legend even without an ESPN image. To add a player: find his ESPN id (search/v2 uid) and NBA id, open both files, check the NBA one is not the placeholder size. A practice app, not for distribution: they are NBA.com's images.

## Seasons, playoffs and brackets
Standings, Playoffs (with Play-In) and NBA Cup are separate drawer screens, each with a season picker (Standings back to 2000-01, Playoffs to 2002-03 (ESPN's notes name the round only from 2009-10 on; before that `inferPlayoffNotes` in `lib/league/bracket.ts` works it out: a team's k-th series is round k, the conference comes from that season's standings, and the notes are rewritten in ESPN's own later format so everything downstream reads them unchanged; checked against real data, every season 2003-2009 rebuilds to the right champion; 2000-01 and 2001-02 miss games on ESPN's side, so they are not offered), Cup to 2023-24). Past-season
standings come from `site.api.espn.com/apis/v2/.../standings?season=YYYY` (a different shape; `fetchStandings`
handles both). Playoff and play-in games are tagged by note in team schedules (`?season=&seasontype=3|5`), the
same trick as the Cup: `fetchTaggedGames` collects them, `src/lib/bracket.ts` builds series, rounds and tree layout
(seeds 7 and 8 are inferred as 9 minus the top seed). `Bracket` shows Rounds or a drawn tree; a tap on a series calls its `onOpen(series)`: a playoff series pushes the Series screen (below); a play-in game or a Cup knockout game is one game, not a series, so its card opens the game itself (`PostseasonView`, `CupContent`).
Finished seasons are cached forever and persisted (see `shouldPersist`). The Playoffs screen has no Playoffs / Play-In switcher: the two panes are a sideways pager (a seasons before 2020-21 has just the bracket) and the title (`PaneTitle`: names that cross-fade with the pager's fractional position, plus a dot per pane) says which one is on screen; the pane you are not on is drawn once the screen has settled (`useAfterSettle`), a skeleton until then; a season change remounts the pager on the same pane. The Bracket's drawn tree scrolls sideways itself, so a swipe that starts on it belongs to the tree, not the pager: use the rest of the page (or the Rounds view) to change panes. Team Leaders is a pager too (`TeamLeadersScreen` + `MetricPage`): one page per stat (all rank the same cached league feed). It is built like the rosters and the day view: `StatPills` (`leaders/components`, equal-width pills so `useStripFollow` can place the strip from the pager's fractional `page`) has a glass highlight that glides with the pager frame by frame; a move of more than two stats jumps the pager in one step under a quick dip of the page while `page` is animated (`jumping`), only the stat on screen and its neighbours are drawn, and the `stat` route param (which links set) is updated when a swipe settles. The strip has a fixed, non-shrinking height: a flex-shrinking strip beside the pager was squeezed and cut the pills. Team-colored surfaces need their own edge: a black team's (Spurs, Nets) card is invisible on its dark page, so the player card, the roster banner and the home card carry a hairline in `onPrimary`, and logos on a team-colored surface use `logoOn(team, theme.onPrimary)` (a red team's dark-background logo is red on red); for a team whose logo is the same red as its card (Houston, `OUTLINED_LOGO` in `lib/theme`) the team card and the player card's watermark draw it with a white outline (`OUTLINE_STEPS`), and so does the selected tile and the confirm button of the team picker (`OutlinedLogo` in `@/components`: the same eight nudged white copies, with the width as a fraction of the logo's size).

## Loading, transitions and gestures
- Performance rules (keep them): the drawer keeps every opened screen mounted, so (1) the team state is a small external store (`state/team-store.tsx`), read with selectors (`useTeamStore((s) => s.currentTeamId)`) so changing team re-renders only what reads it, not every mounted screen; drawer screens read it with `useScreenTeamStore` (same API), which listens only while its screen is focused: the others sit still and catch up with one render when they come back into view, so a team change no longer re-renders (and re-fetches for) every screen you ever opened while the one you are leaving is still animating away; use `useTeamStore` only outside screens (the drawer menu, widget sync, providers). The picker's "Keep the X as my team" label compares with the favorite as it was when the screen opened (`favoriteAtOpen`), not the live one, which flipped the moment you confirmed; (2) `TeamHome` builds everything under the card in a deferred pass when the team changes; (3) the team switcher lights the tapped tile at once and closes before the team changes. Do not freeze drawer scenes or defer a scene's whole content (`react-freeze`, `useDeferredValue` in the drawer layout): it left a blank generic background between screens and while swiping back. Entrance animations are kept only where they carry meaning (tab and mode slides, the team card's deal-in, the pregame header, and a new result arriving in the team card's form row: `FormDots` slides the circles along and fades the new one in, since the persisted schedule can be a game behind when the card opens and the row used to jump); staggered fade-ins on lists and cards were removed. Don't add per-item `entering` back. **A section that turns up after its screen is open comes in the way the key matchup does** (`@/components/Glide`): the section fades in (`entering={ARRIVE}` on its root view) and everything under it glides down instead of jumping (`<Glide>` around each block below it, or `layout={GLIDE}` on its root view; `GLIDE` is a `LinearTransition`, 340 ms). Reanimated animates a layout only when it changes after the first draw, so a screen that is merely opening is not affected, and both follow Reduce Motion. It is for a section that renders nothing until its data arrives (`return null` while loading): the team page's catch-up, next game, series, scores, Cup, season numbers, best player, clips, odds and watchlist (each block under the card is a `Glide`, and the arriving ones carry `ARRIVE`), the past-season screen's result and best-player cards, and the Pregame's key matchup (which shares `GLIDE`). Do not use it on a list that is there from the first frame, and do not make a screen's whole content a `Glide` tree on a drawer screen's first draw (the sections under the team card are built in a second pass, after it).
- Navigation that pushes or pops goes through `src/navigation/nav.ts` (`openDetail`, `pushOnce`, `goBack`), which share a 700 ms lock: a second tap before the screen has finished sliding is ignored, so a double tap on a game card cannot push the page twice (and a double tap on a back arrow cannot pop two). Use `pushOnce` instead of `router.push` for anything new that opens a page. Back arrows call `goBack()` from `@/navigation`, never `router.back()` directly: a game opened straight from a widget, the Dynamic Island or a link has nothing under it, and `router.back()` would do nothing; `goBack` falls back to the home card.
- Long stacks: game, team and player pages push onto each other, and `openDetail` swaps the top page instead of pushing once `MAX_DETAIL_DEPTH` (3) are stacked. There is deliberately no "back to menu" shortcut button (it crowded the headers). `NavDepthTracker` reads the root stack one level down (the navigation state wraps it in `__root`).
- The game page's team logos are drawn once, by `GameLogos`, above the scrolling page (not inside `ScoreHero`): they start on measured slots in the big header and, driven by `scrollY`, ride up and glide into the top bar without ever hiding. `ScoreHero` keeps empty slots and reports their position (`onLogoSlot`); `GameTopBar` only leaves room for them. The top bar also shows the start time (`kickoffLabel` in `lib/date.ts`, device time) as a pill under the matchup, and under "Scheduled" before tip-off.
- Live game header: under each team's name, seven bars show the timeouts left (green = left; ESPN's `timeoutsRemaining`, live games only), fading out as the page scrolls so they never ride under the top bar. While a timeout is on (`timeoutInProgress` in `lib/game/timeouts.ts`: the newest play of a live game is a timeout; ESPN has no flag for it) a "NOP TO" pill sits under the clock ("Official TO" for a TV timeout) and the compact bar does not repeat it. There is no "updated ago" text.
- Loading states are skeletons, not spinners: `Skeleton` / `SkeletonGroup` (one shared pulse) and `ListSkeleton` in `src/components`, plus screen-shaped ones next to their feature (`PlayerSkeleton`, `GameSkeleton`). Query `isPending` decides; never show an empty state while data is still loading.

## Highlights (video)
ESPN's game summary carries a `videos` array (the game's full highlights and single plays, played from the HLS stream, falling back to the one 22 MB MP4: the MP4 made the system player's 10-second skips slow, HLS is cut in short keyframe-indexed segments, adapts from 360p to 720p and has English subtitles; `normalizeVideos` in `lib/espn/video.ts`, `GameSummary.videos`). `Highlights` (`@/components`) is the row of thumbnails with a full-screen player (`HighlightPlayer`, `expo-video`) and is used on the game Summary tab, the team page (`TeamHighlights`: full-game clips of the last four finished games) and the player's Season tab (`PlayerHighlights`: clips from his last six games whose headline names him; ESPN has no per-player or per-team video feed, I tried several). It reads each game's summary through the same cached query the game page uses (`useGameVideos`). ESPN lists the countries each clip is licensed for and Spain is on none of them; `HONOR_VIDEO_REGIONS` (false) decides whether the app respects that list. It is false because this is a personal practice app and its owner chose to show them anyway: flip it to true if the app is ever shared. `expo-video` is a native module: `Highlights` probes for it (`requireOptionalNativeModule('ExpoVideo')`) and shows a "needs a new build" message on a build made before it was added, instead of crashing; after `npx expo install expo-video` run `npx expo prebuild --platform ios --no-install`, `pod install` and a native build.
The player (`HighlightPlayer`) is the system's own full-screen video player: a 1-pt invisible `VideoView` is mounted and sent to full screen with `enterFullscreen()`, so the controls, the close button and the rotation are all the system's and nothing of ours sits on top (a custom control layer, then a custom close button, were tried and dropped); when it is dismissed (`onFullscreenExit`) the row closes it, and a clip that ends goes on to the next. Loading: the system player is presented only once the clip has its first picture (`statusChange` → `readyToPlay`); until then the tapped thumbnail shows a veil with a spinner (`phase` 'loading'), and a tap on another clip meanwhile only swaps the source of the same player (`useVideoPlayer` calls `replaceAsync`, which cancels the download in flight). Opening clips one after another used to leave a black full-screen player frozen on its first second: each tap built a new player buffering 60 s of HLS at once, and presenting over a system player still being dismissed never started (`REPRESENT_GAP_MS` now spaces them). A clip that errors or has no picture after 15 s shows "Couldn't load" on its thumbnail with Retry (remounts the player through `attempt`) and "ESPN ↗" (`GameVideo.webUrl`, the clip's espn.com page, opened with `expo-web-browser`). Quality: ESPN's HLS master playlist lists eight levels, lowest (360p, 0.7 Mbps) first, and the player starts on the first and takes four or five seconds to climb (measured with AVPlayer's access log), so every clip began blurry. `sharpSource` (`lib/espn/video.ts`) reads the master playlist while the thumbnail shows its loading state and the player is given the 720p, 30 fps level with the lowest bitrate directly (`sharpestVariant`; about 2.7 Mbps average, a 16 s clip is about 5 MB), sharp from the first frame; if the read fails it falls back to the master stream. Cost: no adaptive down-shifting on a weak connection and no subtitles (they hang off the master playlist). A local master playlist with the 720p level listed first was tried and AVPlayer would not load it from a file. While the clips of the team and player rows are read (the `useAfterSettle` pause plus a few requests) `Highlights` draws its title with placeholder cards (`loading`, `Highlights.skeleton.tsx`, same measurements as the real row) so nothing below moves; it collapses if there turn out to be none. Placement: the game page puts the clips first on a finished game and after the leaders on a live one, the team page puts them right under Recent Games (results, then the clips of those games), the player's Season tab right after his Form card (how he is playing, then the clips from those games). The calendar's Finals and All-Star marks are keyed by the device's day like its cells (`calendarEvents`, `easternEveningKey` for the All-Star Game, whose tip-off time is not known: 8 pm Eastern). Caching is deliberately not used: expo-video cannot cache HLS on iOS (`useCaching` is for progressive files only), and the MP4 is about 22 MB per 16 s clip against a few MB of 360p HLS. The whole app stays locked to portrait for good (`expo-screen-orientation` plugin, `initialOrientation: PORTRAIT_UP`; `orientation` in `app.json` is `default` so the native project allows landscape at all): only the system player rotates, because expo-video's own full-screen view controller sets its supported orientations (`fullscreenOptions.orientation: 'default'`). Unlocking the app while the video was open broke the layout when it closed in landscape, so the app never unlocks. Needs `expo prebuild` + `pod install` + a native build after the orientation change. `expo-screen-orientation` is pinned to 58.0.3: 58.0.4 uses `ExpoRootViewController`, which the installed `expo-modules-core` (58.0.29) does not have, and the iOS build fails; move both together.

## Performance and stability
- **The first visit to a drawer screen is paid for in the background** (`usePreloadScreens` in `navigation/preload.ts`, used by `(drawer)/_layout.tsx`: `PRELOADED` = Calendar, Team Leaders, Teams, then `PRELOADED_LATER` = Player Leaders, through `router.prefetch`, which renders a drawer screen without focusing it; it only works for a drawer that is the active route, a `prefetch` made from the intro route through a preloaded `/home` remounted the Calendar in a loop). Measured in the simulator with a temporary frame-gap meter and React `Profiler` (JS stalls and UI frames over 26 ms per 250 ms window): a cold first open of the Calendar blocked the JS thread for 177, 330 and 359 ms while it slid in (mount 63 ms of React work, the rest native view creation and layout, plus three more renders during the slide) and dropped several UI frames; the same open after a preload has no mount at all, one JS stall of about 85 ms and one slow UI frame (the menu closing), the same as a second visit. Timers, `useSceneSettled` and prefetching only move work around inside that window; the mount itself is the cost, so move it out of the open. A preloaded screen is unfocused when it mounts, so `SceneFrame` treats it as settled and its second pass (day strip, neighbouring pages, prefetches) runs then too. Add a screen to `PRELOADED` when its first open stutters, and measure it the same way (temporary `Profiler` + `useFrameCallback` meter, `xcrun simctl spawn <udid> log stream --predicate 'eventMessage CONTAINS "[probe]"'`; truncating the log file while `log stream` writes to it leaves NUL padding, so read it through `tr -d '\000'`). **The intro is an overlay, not a route** (`IntroOverlay`, `features/intro/components`, mounted by the root layout when a launch starts on `/`; `IntroScreen` is only the blank route under it), and the app is built underneath it, never while anything moves (building a screen freezes whatever is animating: a timer from the screen's mount landed the home card on the last bounce, starting after the bounce landed it on the ring, and acts with a still beat between them made the intro 4 to 5 s). So `run()`: the native splash is still up (a still picture of the ball) and under it `router.replace('/home')` builds the drawer and the home card (`whenIdle(300, 200)`, capped at 2 s); then `SplashScreen.hide()` and one short continuous animation (`ANIM_MS` 1.6 s: toss and bounces 1.0 s, the court line, the ring from 0.78 s, the wordmark from 0.9 s, the ring's echo from 1.1 s); then, with the finished logo still, `preloadWithin(STEP_BUDGET_MS = 600)` builds Calendar, Team Leaders and Teams one at a time (`preloadStep`, each `whenIdle(150, 100)`: at least that long, then that much quiet counted from the last frame more than 24 ms late): a step that has begun is finished, none begins after the budget, and `endPreloadDrive()` (called as the intro leaves) hands what is left to timers (1.5 s and 1.2 s apart); then the fade (0.32 s). The budget is what keeps the intro short on a slow device, whatever the screens cost. `PRELOADED_LATER` (Player Leaders, light) is built 4.5 s after the drawer mounts. The root layout does not hide the splash while the intro is up (the route changes to `/home` under it); the intro does. The intro cannot be skipped (a tap on it does nothing; it was a skip button before): only Reduce Motion cuts the animation (`noMotion` in `IntroOverlay`). Measured in the simulator (dev): home built under the splash in 1.1 s, animation 1.6 s, one step (the Calendar) in the budget, then the fade: about 2.7 s of animation and fade after the splash goes, 3.8 s in all; a Release build builds faster, so the splash part shrinks and more steps fit (estimated 3 s or less in all, not measured). A first launch (no favorite team) has no drawer to build and goes on to `/onboarding` as before. A launch that a widget, the Dynamic Island or a link opens on another page has no intro (the root layout hides the splash).
- First open of a drawer screen: every drawer screen is mounted on first visit while the menu closes and `SceneFrame` slides it in (520 ms). Its heavy second pass (the rest of a list, a neighbouring pager page, a prefetch, a second pane) must start after that slide, and `useSceneSettled(padMs)` (`@/hooks`, fed by a context that `SceneFrame` provides; true for good once the slide is over, true at once off the drawer and on the first screen after launch) is how: Teams, Team Leaders, Calendar (`DayPager`, `DayPills`), League Wire and Playoffs use it instead of their own timers (350, 700, 900 ms: the shorter ones landed mid-slide). - **Pick'em rows** are `PickGameCard`: the Calendar's `GameCard` with no second row, whose two team sides are the vote buttons (`GameCard`'s `wrapSide` prop wraps each side in a `Pressable`): a tap on a side picks that team (again takes it back), a tap on the rest of the card opens the game; an open side is faintly outlined, the chosen one lit in its team's color (green when right, red when wrong), both lock at tip-off and the side not taken dims. `usePickChoice` (in `PickButtons/`) is the shared pick logic of `PickButtons` (the game page's big tiles, sizes lg and sm) and `PickGameCard`; `PickBadge` lives in `@/components`. A one-line hint above the list says what a tap does.
- **Small changes**: `EventsBack` (an arrow back to the Events hub on Draft, All-Star, Awards and Cup when opened from it), screen titles "Player leaders", "Team leaders", "Injuries and moves", `accessibilityRole="button"` on the pressables that lacked it, Standings rows are plain views (no per-row `entering`), Play-by-play animates layout only for the first four rows, Agenda keeps its `Intl.DateTimeFormat`s at module level, `useGameTeams` waits for the game's own summary, `shouldPersist` reads a one-second cached set of the newest finished games. Dead exports removed (`HistoryIcon`, `WireIcon`, `CHAMPION_GOLD`, `useHasSpotlight`, `nbaToday`).
- **Yearly tables** (`tests/yearly-tables.test.ts`): fails when `CHAMPIONS`, `CUP_CHAMPIONS` or the All-Star `GAME_DAYS` fall behind the calendar (champion after June, Cup winner in the new year, All-Star day after February), so the new entry is not forgotten.
