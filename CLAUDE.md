# Courtside: project notes for Claude Code

Practice app, not shipping to stores. The owner is an experienced React Native
developer who wants to explore animations and native features.

## Stack
- Expo SDK 58, React Native 0.88, React 19.3, React Compiler on
- Expo Router 58 (drawer is built into `expo-router/drawer`, no @react-navigation/drawer)
- Reanimated 4.7 + react-native-worklets (`scheduleOnRN`, not `runOnJS`)
- Gesture Handler 3.3: use the hook API (`usePanGesture`, etc.) with `GestureDetector`
- TanStack Query for ESPN data, AsyncStorage for the favorite team

## Conventions
- Routes in `src/app/` are one-line re-exports of a screen (`export { StandingsScreen as default } from '@/features/standings'`);
  layouts (`_layout.tsx`) stay there. Everything else lives in `src/features`, `src/components`, `src/hooks`, `src/lib`,
  `src/navigation`, `src/state`, `src/widgets`
- **One folder per component or screen**, named in PascalCase, holding everything that belongs to it:
  ```
  features/game/components/ShotChart/
    ShotChart.tsx          the component
    constants.ts           top-level constants it uses (add `use<Name>.ts`, `types.ts`, `<Name>.skeleton.tsx` the same way)
    ShotChart.stories.tsx  its Storybook stories (only if the stories are about this one component)
    index.ts               `export * from './ShotChart'`
  ```
- `features/<name>/` groups one area of the app: `components/` (its building blocks), `screens/` (one folder per screen),
  `stories/` (stories that span several of its components), `utils/` (helpers shared by its components), and an `index.ts` that exports
  `components` and `screens`. Features: `allstar awards calendar compare cup draft game home intro leaders news onboarding player playoffs search standings team watchlist wire`
- `components/` is only for pieces used by several features: `Screen` (header, loading/error states), `Glass` (a surface drawn as iOS 26 Liquid Glass through `expo-glass-effect` and as a plain translucent view on older iOS or a build without the module; always the dark variant, for things that float over content: Rule of thumb: glass is for floating controls and for the selection, not for every resting item (each one is a native effect view), and it carries a faint white `FROST` tint by default because dark glass on the dark app reads as a hole. `Chip` (+ `ChipText`) is the one filter/mode chip (StickyBar periods, play-by-play filters, shot-chart players, game log stats, Cup and Bracket rounds, the League and Team Leaders stat rows in size `lg`): the chosen chip is glass, optionally tinted with `color`, the rest a plain pill. The `Segmented` thumb, `SeasonButton`, `SearchInput` (`bare` when a screen draws the pill itself around an icon, as Search does, so no second glass box sits inside it), the drawer's search row and Mine/Change pills and the Calendar's `ViewSheet` are glass too. `GlassButton` is its round or pill-shaped button: the header's menu/back and `IconButton` circles, the game page's back and star, the player page's back, star and Compare in the team's tint; the Calendar's Today pill), `Segmented`, `Chip`, `Collapsible`, `Expandable`,
  `RollingNumber`, `LiveFlash`, `DataHealthBanner`, `SeasonPicker`, `SearchInput` (search field with a hand-drawn placeholder: iOS puts TextInput's own placeholder below the caret with a custom font), `Form` (W/L dots and chips), `HeadToHead`, `Icons`, `Basketball`, `NbaLogo`, `TeamMark`
- Import rule (ESLint enforces it): use a folder's index, never a file inside it. From outside a feature: `@/features/game`; shared UI:
  `@/components`; also `@/lib/espn`, `@/hooks`, `@/state`. Inside a feature: a sibling component is `../ShotChart`, a screen
  reaches the feature's components via `../../components`. A new component = new folder + add it to the feature's `components/index.ts`.
  A feature may use another feature only through its index (e.g. `team` uses `@/features/watchlist`); keep these acyclic.
- `lib/`: `espn/` (client, teams, schedule, standings, game, scoreboard, players, player-profile, team-stats, tagged), `game/`
  (game-model, quarter-stats, period-stats), `league/` (bracket, cup, team-stats, titles), `theme/` (colors + team marks), `widgets/` (widget props, snapshot builders, timeline, live-game: pure); `date.ts`
  and `data-health.ts` stay single files
- `navigation/` (`openDetail`, depth tracker), `widgets/` (iOS widgets and the Live Activity, one folder per widget like a component; its `index.ts` exports only `WidgetSync`, because the widget views import native modules and are loaded lazily by `WidgetSync/sync.ts`). Everything pure about widgets (props types, snapshot builders, the timeline, `live-game`) lives in `lib/widgets/` (`@/lib/widgets`), which Node tests can load
- Colors come from `teamTheme(team)` in `src/lib/theme`; don't hard-code team colors
- Pick logos with `logoOn(team, onColor)` so they read on dark or light backgrounds
- Fonts: `fonts.display` (Big Shoulders Display) for headlines and numbers, Barlow for body
- Animations run on the UI thread; avoid React state inside gesture or sensor callbacks
- No icon library is installed; icons are hand-drawn SVGs in `src/components/Icons`

## Design system
The look is dark, team-colored and scoreboard-like: Big Shoulders Display for numbers and headlines, Barlow for text, a dark page tinted by the selected team, `Liquid Glass` only on small floating controls. Everything lives in `src/lib/theme` (tokens, `teamTheme`) and `src/components` (primitives); `CLAUDE.md` is its documentation, Storybook (`npm run storybook`) is its picture.
- **Tokens** (`lib/theme`): `palette` (arena, chalk, muted, maple, and the meanings `win`, `loss`, `gold`: never write a green, red or gold hex, and `live` is the win green), `surfaces` (`faint` / `card` / `raised`: the translucent white layers cards, rows and fields are made of: never write `withAlpha('#FFFFFF', 0.0x)` for a background), `radius` (8 / 12 / 16 / 22 / pill), `space` (2 / 4 / 8 / 12 / 16 / 24 / 32), `fontSize`, `motion` (160 / 240 / 450 ms, easing `Easing.out(Easing.cubic)`) and `textStyle` (`sectionLabel`, `emptyTitle`, `emptyText`: spread into a style). They are the values the app already used most, so a screen moved onto them barely changes. The older screens still hold ad-hoc radii, font sizes and spacings (about 30 radii, 27 font sizes at the last count): move them onto the scales as you touch them, and use the scales for anything new. Widgets and the Live Activity run in their own runtime and cannot import the tokens: they repeat the hex values.
- **`teamTheme(team)`** is the only way to get a team's colors (`TEAM_PALETTE` in `lib/theme/theme.ts` replaces ESPN's pair for nine teams whose look was another team's: the Pistons, Knicks and 76ers were one royal blue, the Pacers, Nuggets and Pelicans one navy, the Nets and Spurs one black, the Lakers and Kings one purple, the Wizards one more red among Raptors, Bulls, Rockets and Hawks. Now: Pacers lemon gold with a navy stripe, Pelicans a dark dirty gold (`#957F2C`, white text 3.9:1) with a navy stripe, Nuggets left on ESPN's own navy and gold (a bright blue and a deep royal blue were both tried and rejected), Knicks a deeper orange (a shade under their own, so white text reads on it, 3.1:1) with blue, Spurs silver with black, 76ers ESPN's own blue (the pair was left alone: it was the jersey blue the owner liked), Pistons a deep navy with red, Wizards a vivid blue with red, Kings a lighter violet, Hawks a scarlet (the Rockets' red was the Hawks' too) with their own gold, Raptors charcoal with their red as the accent (ESPN's red was the Bulls' to 3.9 in Lab, and the reds left no free slot; on that card they wear their own red logo, `COLOR_LOGO` in `lib/theme`, which `logoOn` honors, instead of the white one, and the player card's watermark of it is drawn at 0.18). The key is ESPN's lower-cased `color|alternateColor` pair, so it works for a team from any feed and a team whose ESPN colors change falls back to them; `teamColors(team)` gives the pair a team is drawn in and `matchupColors` uses it. The cards were picked to be at least 16 apart in CIE Lab from every other card, where ESPN's were 0 for three pairs and 3 to 11 for six more; the reds (Hawks, Bulls, Raptors, Rockets, Trail Blazers, Heat, Cavaliers) were left as they are on purpose, told apart by their accents and logos. Text on a card is near-black from a luminance of 0.30, where white falls under 3:1 (it was 0.45, which no card sat between until the Pacers and Knicks). `tests/theme.test.ts` keeps the groups apart and no two cards equal).  `primary` / `secondary` are ESPN's; `background` is the dark page; `onPrimary` the text on a card; `brand` the team's own bright color for FILLS and graphics (bars, washes, dots), which can be as dim as 2:1 on its own page; `accent` is `brand` lifted until it reads on the page at 4.5:1, for anything READ (numbers, labels, icons, the tab underline); `stripe` the card's stripe; `edge` the line along a team card that shows against both the card and the page (a black or navy team's card is within 1.2:1 of its page without one). `tests/theme.test.ts` holds these guarantees for all 30 teams (colors recorded in `tests/fixtures/team-colors.json`); `contrast()` and `ensureContrast()` are exported. Never read `team.color` directly.
- **Primitives** (`@/components`): `Card` (neutral `tone`, or `team={theme}` for a team-colored card with its edge), `Pill` (muted / gold / win / loss, or `on={theme.onPrimary}` frosted on a card), `Button` (primary / secondary / quiet), `SectionLabel`, `EmptyState` (`placement` top or center, optional icon and action), `Chip`, `Segmented`, `Glass` / `GlassButton`, `Skeleton`, `Screen` header, `Icons`, `Trophies`, `CardLights`. Reach for one of these before writing another rounded translucent box, "Try again" button, uppercase label or empty state.
- **Seeing it**: Storybook "Foundations / Team theme board" (all 30 teams: card with and without edge, accent before and after with the ratio, stripe), "Foundations / Primitives and scales", "Foundations / Theme".
- **Accessibility**: Reanimated animations follow the system's Reduce Motion (stated in `_layout.tsx` with `ReducedMotionConfig`; the explicit `useReducedMotion` checks are for what Reanimated cannot see: the gyroscope tilt, the intro, skeleton pulses). Text is not capped for Dynamic Type (React 19 dropped `defaultProps`, so a global cap would need a themed `Text`): cards and pills have fixed heights, and larger text sizes are untested. The app is dark-only on purpose (`userInterfaceStyle: dark`).

## Data
ESPN endpoints are undocumented and may change. All parsing lives in
`src/lib/espn.ts`. If a field shows "–" in the UI, inspect the live response
and fix the normalizer there rather than in components.

Per-quarter and per-half player/team stats are not in ESPN's box score. `src/lib/game/quarter-stats.ts`
rebuilds them from the play-by-play feed (`Play[]` from `fetchGameSummary`), and it also powers the
win-probability chart and play-by-play tab. Check accuracy against a game with
`node --experimental-strip-types --import ./tests/register.mjs scripts/validate-quarter-stats.ts <gameId>`; counting stats match
the box score, derived plus-minus can drift by ±1.

Other data sources beyond the main ESPN site API: the common/v3 `gamelog` endpoint (player game log) and `search/v2` (player search, used by Search and Compare: it knows retired players like Garnett, Nowitzki and Gasol, which `common/v3/search` does not, and it lists every sport and league at once, so `normalizePlayerSearch` keeps the rows whose uid is NBA (`l:46`) and that have an `image` (ESPN has no photo of the unknowns: obscure old players, two-way signings who never played) from a 50-row page; it names the team but has no id, so `usePlayerSearch` matches the name against the cached team list and a retired player's defunct club just has no team) and core-API team statistics (home screen team season card).
Team ranks (home card, Compare > Teams) are computed in `src/lib/team-stats.ts` from the one-call
`statistics/byteam` feed (`fetchLeagueTeamStats`); ESPN's own per-team `rank` fields are unreliable for
derived stats like 3P%. Player career tables come from the common/v3 athlete `stats` endpoint.
Scoreboards are keyed by US Eastern date (`toNbaDateKey()`), but days on screen are the device's own: `useGamesOnDay(day, today)` reads the one or two scoreboards that hold a local day (`scoreboardKeysFor`) and keeps the games that start on it (`startsOnDay`); on today a game that is on right now is listed too, even if it started the evening before. The Calendar day pages, Month cells, home scores strip and "today" (`localToday()`) all use it. Only the Live Activity and the widgets still think in Eastern dates (the Activity reads both today's and yesterday's board).
Worklet gotcha: never call plain JS helpers (e.g. `withAlpha`) inside `useAnimatedStyle`, and don't use
object spread in gesture hook configs; neither shows up in `tsc`, both crash at runtime.
React Query's cache is persisted to AsyncStorage for slow-changing keys only (see `PERSISTED` in `src/app/_layout.tsx`).

## Pregame, form and head-to-head
`normalizeGameSummary` returns `pregame` (`winProb` from ESPN's matchup predictor, `odds` from `pickcenter` when a book has posted a line,
`form` = last five results per team from `lastFiveGames`). Odds are US moneylines converted to decimal (`moneylineToDecimal`); many games
have no line yet, so every part is optional and the card hides what's missing. There is no head-to-head feed: `fetchHeadToHead` reads one
team's regular-season and playoff schedules season by season until it has 10 finished meetings (`summarizeHeadToHead` in `lib/league`).
The Summary tab shows odds, form and head-to-head before tip-off; Compare > Teams shows head-to-head too.
All-Star selections are not in ESPN's awards (only the All-Star MVP): `fetchAllStars` reads each All-Star Game's roster from its scoreboard day (2003 on, dates in `lib/espn/all-star.ts`, add the new February each year) and `HonorsCard` shows them as "NBA All-Star". The playoff bracket is one tree (East above West, Finals as the last column, `BracketSection.byConference`); the play-in is a per-conference bracket (7v8 and 9v10 feed the 8th seed game).
What a game links to depends on its kind (`GameSummary.kind`, from ESPN's `header.gameNote` and `header.season.type` by `classifyGame` in `lib/espn/common.ts`; `season` is `header.season.year`) and is decided by `MatchupPlace` (game feature): regular season, the standings as below; playoffs, the pushed `/matchup-playoffs` (the bracket of that season, opened on the round of the series, both teams' series card lit); play-in, the same route on its Play-In pane; Cup group play or knockout (the Cup final too: it is in no standings), the pushed `/matchup-cup` on the groups (the group of the two teams first, their rows lit) or the knockout bracket; All-Star and preseason games, no link (they are in no table), and a playoff game before 2002-03 none either (ESPN's schedules have gaps there, the bracket cannot be rebuilt). These pushed screens are `PlayoffsScreen` / `CupScreen` with `pushed`, locked to the game's season (no season picker), and the lit teams travel as `Spotlight` (`@/components`, a context read by `SeriesCard`, `MiniSeries`, `GroupCard`, `Bracket`). A playoff game is marked like a Cup game: `PlayoffBadge` (playoffs feature; `playoffTag` in `lib/league/bracket.ts`: "WCF · G2", "R1 · G3", "FINALS · G4", "PLAY-IN") on the Calendar's `GameCard` and Agenda, and the same tag after the matchup in the game page's top bar (`GameTopBar` `tag`, "NBA CUP" for the Cup). In a playoff game each team's seed shows as "(3)" after its abbreviation (game card and game header; `usePlayoffSeeds`, from the season's playoff games through `playoffSeeds`, so the 7 and 8 seeds from the play-in are right; ESPN publishes no seed, and the hook shares the `postseason` cache and is persisted) and the series sits under the status ("ORL leads 3-2", "NYK won 4-2", "Tied 3-3": `seriesLine` over `competitions[].series.summary` on the scoreboard and the playoff entry of `header.competitions[0].series` on the summary; ESPN's text is the series as it stood after that game, so a finished game shows its own result and one still to come shows the present state). The Bracket opens on the drawn tree, scrolled to the game's series, when it was opened from a game (`Spotlight`). Every game links to Standings (`openStandings(teamIds, date)` in the game feature): the screen reads `teams` (comma separated ids, highlighted in matchup colors, opens the shared conference or the league table and scrolls to them) and `season` params. Before tip-off the Summary tab shows the standings card (same conference: that table with both rows lit; different: each team's place).
The drawer (`components/DrawerMenu`) is grouped into what is yours (no heading: Team card, Calendar, Watchlist, which holds players and games alike), League (Standings, Player leaders, Team leaders = teams ranked by a team stat, Teams = all 30 teams' rosters in a pager (the old All teams list is gone: its pills strip is the picker, and the drawer search finds teams too), Compare = players or teams) and Tournaments (`SECTIONS`) with a search entry on top (opens `/search`). Team card and Calendar are the two main screens: a Calendar button sits beside the menu on the Team card (`ScreenHeader`'s `afterMenu`); the Calendar has no button back, the menu is its way out; `SceneFrame` also settles each screen in when you reach it (content eases from 22pt right to rest over 520 ms with an ease-out quint curve, no scale, and the fade is a veil in the menu color over the screen, not the screen's own opacity (that forced an offscreen render of every card per frame), started two animation frames after the screen's first draw so a heavy first render does not eat the start of the move; the first screen after launch skips it, the intro hands over, and it plays for every deliberate trip to a drawer screen (menu or any button, plain `router.navigate`), but not when a game, player or team page on top of it closes and the same screen shows again (`returningFromDetail` in `@/navigation`, with `lastScene` in `SceneFrame` so a button on a detail page that goes to a different screen still slides): returning to a screen from a game or player page also focuses it, and sliding it in then looked like the menu dragging open; opacity never starts at 0 or the menu's color would show), `SceneFrame`, wired through the drawer's `screenLayout` (a module-level function: an inline one rebuilds every screen), draws corners, shadow and edge on top of each screen while the menu is open, without clipping the screen (clipping made opening screens lag). Standings opened from a game is the pushed `/matchup-standings` route, so back returns to the game. Compare opened from a player page or a team page is likewise the pushed `/matchup-compare` route (`CompareScreen pushed`, back arrow in the header; the drawer's own Compare keeps the menu button). The drawer's edge swipe is only on while a drawer screen is on top (`swipeEnabled` from `useSegments()[0] === '(drawer)'` in `(drawer)/_layout.tsx`): a game, player or team page opened over it leaves the drawer mounted underneath, whose edge swipe would otherwise catch the back swipe and drag the screen below open like the menu. A new screen = a route file, a `Drawer.Screen`, and an entry in `SECTIONS`.
The Teams screen (`RosterScreen`, route `(drawer)/teams`; `/roster` redirects to it) is a horizontal pager with one page per team (`TeamRoster`), alphabetical, opening on the team you are viewing. Its position is a fractional `page` shared value: the screen background (the team's color, header included), the `TeamPills` strip with its team-colored outline and the strip's own scroll all follow it. Performance rules: only five pages are mounted (`windowSize={5}`); a move of more than two teams jumps the pager in one step while `page` is animated separately (`jumping`), instead of scrolling through pages; rows are built only for the page last settled on and its neighbours, every other page shows the static `RosterSkeleton` (no pulsing skeletons: dozens of animated views per page); once at rest, rosters and first headshots of the teams two swipes either way are prefetched into the React Query cache. Swiping does not change the app's selected team; a tap on the team banner at the top of a page does (`viewTeam`, then `/home`): the banner says "Team page" and is the way from a roster to that team's card.
The player page is split into `PlayerCard` and `PlayerTopBar` (`features/player/components`; the screen keeps the data, the tabs and the scroll). `PlayerCard` is a trading card, 74% of the screen wide and at most 300 pt (`playerCardSize`, 1.4 times as tall as wide): the team color with its logo as a watermark (white-outlined and stronger for `OUTLINED_LOGO` teams, and on this card for the Hawks and Bulls too: `OUTLINED_WATERMARK`; the detailed Raptors, Wizards and Cavaliers logos are not outlined, which smeared them, only drawn at 0.3 instead of 0.12: `STRONG_WATERMARK`), his photo melting into the footer, his big faint number, his name under a stripe in the secondary color, small frosted pills (position, height, age) and, upper left, his trophies as small hand-drawn gold trophies with their short label (Champion, NBA Cup, MVP, Finals MVP, ECF / WCF MVP, DPOY, ROY) on dark pills (gold on a dark pill reads on every team color, the yellow Warriors card included; a gold-on-gold label did not; the drawn trophy alone did not say which award it was, so the words stay): the championship (the Larry O'Brien icon; the titles the Honors card counts from the career seasons, since ESPN's honors list has none), the NBA Cup (`cupSeasons` / `CUP_CHAMPIONS` in `lib/league/titles.ts`, the same roster rule as titles, winners checked against ESPN's finals: 2024 LAL, 2025 MIL, 2026 NY), MVP, Finals MVP, conference finals MVP (both conferences count as one trophy), Defensive Player of the Year and Rookie of the Year from the profile's honors, each with ×n when he has more than one, then "Retired" / "Free agent" as text when he has no team. The profile (honors) and the career (titles, Cups) are read as the page opens, not after it settles, so the trophies are not late (they are cached and persisted); each fades in when it arrives. The league ranks and the All-Star list (read ahead for the Info tab) still wait for `useAfterSettle`. The five award trophies (`components/Trophies`: `MvpTrophyIcon` a ball on a column, `FinalsMvpTrophyIcon` a ball in a hand, `ConferenceMvpTrophyIcon` a ball in a ring, `DpoyTrophyIcon` a raised hand, `RoyTrophyIcon` a star) are drawn on the same 24 x 30 canvas as `LarryOBrienIcon`; they are approximations (real trophy photos were considered and not used: copyrighted designs, not tintable, and they do not read on every card), and the Honors card uses them too. Match "Finals MVP" with `/(^|nba )finals mvp$/i`: "NBA Eastern Conference Finals MVP" contains the same words and is its own award) and the season line: five averages (PPG, RPG, APG, SPG, BPG; no minutes: tried as a sixth cell and as a corner pill, it read as clutter or as an award; skeleton blocks until they arrive, never dashes; for someone with no current season, retired or unsigned, they are his career averages from the career line (`careerAverages`), named "CAREER" beside the stripe and without ranks, and the compact header says "Career ·"), each with his league rank under it when he is in that stat's top 50 (`useLeagueRanks`, the same cached leaders feeds as League Leaders). The numbers live only on the card: the Season tab does not repeat them (it starts with Shooting, with the games played), and the Career tab lists seasons newest first (a traded season reads the team he finished with, then the combined line, then the earlier team(s): ESPN sends it oldest first with the total last; `arrange` in `CareerTable`), with this season's row(s) washed in the accent color and tagged "NOW". The card tilts like the team card and shares its light (`CardLights`, `@/components`); its edge is `theme.edge` (the secondary color when it is bright and unlike the primary, else `onPrimary`). The pills are deliberately NOT Liquid Glass: glass has to sit outside the 3D-tilted layer, and over a tilting card the glass tags on the side that tipped toward you dropped out (with a parallax on the layer, and again without one); frosted pills drawn on the card tilt with it and never drop. `PlayerTopBar` keeps back, star and compare as glass buttons (compare is icon-only) and shows a compact photo, name and season line between them once the card has mostly scrolled away (`compactProgress`, eased, with a hysteresis like the team page's title: the same pattern as `TeamHome`'s `titleShown` / `titleProgress`). Not built, to think about on the Rosters screen: swiping between a team's players. A player link carries the team he played for in that game; when that roster no longer has him (traded, retired, never signed) `PlayerScreen` builds the page from `fetchPlayerBio` (the athlete record), so anyone ESPN knows can be opened. The game log merges regular season and playoffs (`playoffs` flag).

Calendar Month and Agenda read whole seasons: `fetchTeamSeason` / `useSeasonGames(teamId, season)` merge a team's regular season, play-in and playoffs (the month in view picks the season, Agenda has a season button), so old months fill in; day view reaches any date through the scoreboard. Finished seasons are cached forever.
Month also marks the All-Star Game (ESPN's NBA logo with a gold star) and NBA Finals games (a hand-drawn Larry O'Brien trophy, `LarryOBrienIcon`; ESPN has no trophy or All-Star artwork) for every team (`calendarEvents` in `lib/league`): the All-Star day comes from the hard-coded list in `lib/espn/all-star.ts`, the Finals games from the season's playoff notes (read only for months that can hold a Finals).

Starring: players and games both go to the Watchlist (`useWatchlist`: `players` / `toggle`, `games` / `toggleGame`, each persisted under its own AsyncStorage key). The game star sits in the game page's top bar (`GameTopBar`, right side, stays in the compact bar); a `WatchedGame` keeps both teams' abbreviation and logo and the start time so the Watchlist screen can list it at once, then `WatchGame` fills in the score and status from the game's own (cached) summary. The favorite-team screen says "Keep" instead of "Make" for the team that is already yours.

## NBA Cup
ESPN has no Cup standings feed, but Cup games carry a note ("NBA Cup - Group Play") in schedules, scoreboards and
game summaries (`cupStage`). `fetchCupGames` reads all 30 team schedules (future games included); `src/lib/cup.ts`
rebuilds the six groups from who plays whom and computes standings (wins, head-to-head, point differential) and the
projected eight-team field. Group letters aren't published, so groups are numbered "East 1".. "West 3".

## NBA Draft
Drawer screen under Tournaments (`features/draft`, route `(drawer)/draft.tsx`, icon `DraftIcon`), a year button in the header (`SeasonButton` + `SeasonSheet`, the same sheet as Playoffs and the Cup, given its own list of years, written as a calendar year, "2026", not "2025-26") over one class, 2003 on (`draftSeasons()`: every June to the latest that has happened; ESPN's 2000-2002 drafts are empty lists): `DraftHero` (year, pick count, how many came from abroad or high school, the No. 1 pick) and one `PickRow` per pick under "First round" / "Second round" headings (number, player, size, college, the team with "via trade" on a traded pick; the favorite team's picks outlined). A tap on a row opens ESPN's pre-draft scouting report under it (plain text from ESPN's HTML, `scoutingText`, with the big-board rank) and a way to the player's page; a player with no report opens it at once. Data is `fetchDraft(season)` in `lib/espn/draft.ts` (`useDraft`, persisted under `draft`, a finished one never changes): one call for `draft/rounds` (every pick with `$ref`s to its player and team), then each player's record (about 60 calls) and each distinct college's (name), all at once, about 2 s. Types are `NbaDraft*` (the plain `Draft` is one player's own draft slot in `player-profile.ts`). From 2019 a player's record links to his NBA page (`nbaId`: his photo and page); before that it links to a college page whose id is not his NBA id, so `openDraftPlayer` finds him by his exact name in the player search, and the row shows the college's logo (or his country's flag, from a club abroad) in place of a photo. A pick's team is the franchise's current ESPN team id, so a 2003 Sonics pick shows Oklahoma City. A pick not yet made has no player: a row with "To be made". Tests: `tests/draft.test.ts` over trimmed real 2025, 2024 and 2005 records; stories: "NBA Draft".

## News
Drawer screen "News" under League (`features/news`, route `(drawer)/news.tsx`, `NewsIcon`) and the pushed `article/[id]` page. `fetchNews(teamId?)` in `lib/espn/news.ts` reads the site API's `news?limit=50` (the league's, or one team's with `&team=`; `useNews`, read afresh every 5 minutes, not persisted): each article has a type (`Recap`, `Preview`, `Story`, `HeadlineNews`, `Media` = `NewsKind` recap / preview / story / news / video), a headline, a one-line summary, pictures, the teams it is about (`categories` of type `team`) and a game id (`event`). A recap's and a preview's pictures are generated matchup images; a story's `header` photo is picked first (`pickImage`). `NewsScreen` is a chip strip (All, your team's own feed, Recaps, Previews, Stories = story + news, Videos) over a list of `ArticleCard`s, the first one a lead with a wide picture. ## Awards and Game Score
- **Awards** (`features/awards`, route `(drawer)/awards.tsx`, drawer "Awards" under Tournaments, `MedalIcon`): a season button in the header (`SeasonButton` + `SeasonSheet`, as on Playoffs and the Cup, offering the seasons of `awardSeasons()`) over one season, from 1999-00 (`AWARDS_FROM` 2000; ESPN has them back to 1980 and the older years were left out on purpose) (`awardSeasons()`: the latest is the season that finished, or the current one from April, when its awards are being given), `AwardsHero` (the years and the MVP; the champions are deliberately not here, the Playoffs and Cup screens show them) and one `AwardSection` per group (Season awards, Playoffs = Finals and conference finals MVPs, More awards, All-NBA, All-Defensive, All-Rookie, NBA Cup); an award with one winner is a row of a shared card (`WinnerRow`), an award with five (a team) a card of its own in court order. Data is `fetchSeasonAwards(season)` in `lib/espn/awards.ts` (`useSeasonAwards`, persisted under `seasonAwards`, a finished season never changes): the season's `awards` list, each award's record, then each winner's athlete record (about fifty requests, all at once). **ESPN holds only the winners**: no voting, no runner-up, so there is no "top 3" of a past season (the sportsbook's odds are the only favorites, in League Leaders "ODDS"); the `note` on a winner is junk ("Test Note"). A winner's team is the franchise's current ESPN id (a 1996 Sonics winner shows Oklahoma City, as on the Draft screen), and the position ESPN gives is today's record's ("NA" for the early years), used only to put a team of five in court order. Tests: `tests/awards.test.ts` over trimmed real 2025, 1996 and 1980 records; stories: "Awards".
- **Courtside Rating** (`lib/game/game-score.ts`, the `CR` column of the box score; the legend sheet says "CR - Courtside Rating"): ESPN publishes no per-game player rating, only the box score, so the rating is the app's own: Hollinger's Game Score (`PTS + 0.4 FGM - 0.7 FGA - 0.4 (FTA - FTM) + 0.7 OREB + 0.3 DREB + STL + 0.7 AST + 0.7 BLK - 0.4 PF - TOV`, raw: 10 is an average game, 20+ very good) turned into a 1-10 rating by `ratingOf`, a straight line between `RATING_POINTS` (raw 0 is a 5, 10 a 7, 16 an 8, 25 a 9, 38 a 10: a 40-10-10 game on good shooting): so 5 is already bad, 6-8 is the range of a typical rotation player, 8+ very good, 9+ elite. For the whole game only (the column is hidden under a period filter, where a quarter cannot be put on that scale), and not for a player under `MIN_RATED_MINUTES`. **While a game is on the rating is a projection of the final one** (`projectedRating` in `game-score.ts`): the raw Game Score is a count, so a young game would rate everyone low. It is the score so far plus what he can be expected to add in the rest of the game, `rate * (min(40, minutes / fraction) - minutes)`, the rate leaned toward a typical player's (`PRIOR_RATE` a third of a point a minute, `PRIOR_MINUTES` 8) while he has played little; `fraction` is the minutes both teams have played over 240 (`gameFraction`: a live box score has no clock), and at 1 it is exactly the finished rating. `useLiveRatings` (`BoxScoreTab`) takes the ratings when the tab opens and again once four more minutes of the game have been played (REFRESH_TEAM_MINUTES 40, about three or four times a quarter), never on a play: they stand still between refreshes and a note under the view switch and the legend say they are projected (5: garbage time reads as a bad game). It is drawn as a solid square in the color of its band (`ratingTone` in `lib/theme/tokens.ts`, from the rating as shown to one decimal): under 6 red, 6-7 orange, 7-8 green, 8-9 light blue, 9+ solid blue (the user's own list), the number white on every band (a 10 is written "10", not "10.0"), sharp corners (`RatingSquare`: 26 pt in the detailed view, 30 in the default one); a player with none shows a dash. Retune `RATING_POINTS` if the user finds it too kind or too harsh. The box score opens sorted by points, highest first, and the column you chose stays chosen when the period filter changes (only the rating, which a period does not have, falls back to points until the whole game is back; among equals the one with more minutes comes first, which puts who played in a quarter above who did not); a tap on a column header sorts by it. Tests in `tests/game.test.ts` and `tests/theme.test.ts`.
- **Box score views** (`features/game/components/BoxScoreTab`, `LegendSheet`): a "Detailed view" switch over the table (off at first, not remembered). The **default view** (`SimpleTable`) is a bigger row per player, 48 pt photo with a gold "Starter" tag over its bottom edge (plus the gold edge on the row), name and "jersey position" under it written out ("7 Forward", `positionName` in `lib/game/position.ts`; the detailed view keeps "7 F"), rows 58 pt high, and four columns that fit with no sideways scroll: CR (only for a finished game), PTS, REB, AST, and a TEAM totals row. The **detailed view** (`DetailedTable`) is the old table, every stat column, with the player column (photo, name, jersey and position, the CR square) pinned: `DETAIL_COL_FULL` 192 pt at rest, shrinking to `DETAIL_COL_SHRUNK` 150 over the first `DETAIL_SHRINK_AT` 56 pt (`detailColWidths`: without the rating, under a period filter, both are `RATING_BOX` + 8 narrower, so no room is kept for a square that is not there) of the stats' scroll (an animated `width` from `scrollX`: the name is cut short, the rating stays beside it), a soft shadow on the pinned edge and a thin `ScrollIndicator` under the column names (a track and a thumb; the visible width is worked out from the table's width and the same shrinking curve, nothing is measured while scrolling; hidden when everything fits). Both tables sort by a tap on a column name (`SortHeader`, the arrow hugs the name; default points, a period filter minutes; switching to the default view drops a sort by a column it does not have) and carry a "Legend ⓘ" button (`LegendButton`) in the header's corner that opens `LegendSheet`, a bottom sheet animated like the Calendar's view sheet: what every column stands for, the rating's note and its color bands, and the Starter tag. The old "tap a column to sort / gold edge" line is gone; only a period filter still prints a note ("stats rebuilt from play-by-play").

## Odds, League Wire, power index and the team page
- **Odds** (`lib/espn/futures.ts`, `useFutures(withAthletes)`): ESPN's futures feed is one sportsbook's (DraftKings') American moneylines for the title, each conference, MVP, ROY, DPOY, Sixth Man, Most Improved, Clutch and Coach of the Year. A "chance" is the line's implied probability scaled so a market adds up to 100% (the margin removed); it is the book's opinion, never ESPN's, and the UI says so. The team page's `TitleOdds` card (title, conference, "Nth favorite") asks for the team markets only (`withAthletes` false), and so does the Team Leaders "Odds" page (`OddsPage`: all thirty teams' title chance, favorite first, with the conference chance); the League Leaders "ODDS" tab (`AwardOdds`, the player awards only: the title odds moved out of it) asks for the award markets too, whose favorites' names, photos and teams are one record request each (about forty), which is why the two are separate queries. A coach's id is not a player's: no photo, no page. Hidden when a team is not in a market (no markets in the offseason).
- **League Wire** (`features/wire`, route `(drawer)/wire.tsx`, drawer "League wire" under League, `WireIcon`): a sideways pager of two panes like the Playoffs screen, no switcher: the title is `PaneTitle` (`@/components`, moved there from the playoffs feature since two screens use it: the pane names cross-fade with the pager's fractional position, a dot per pane), the Moves pane is a skeleton until the screen has settled or is swiped to; `lib/espn/wire.ts`, ESPN's league-wide `injuries` (every team's report, about 90 players in season: status Out / Day-To-Day, what and where, expected return, ESPN's one-line note) and `transactions` (the season's moves, newest first; `?limit=` is the page size, 40 more per "Show earlier moves"). Injuries are grouped by team (a count beside each, the favorite team first) with an All / Out / Day-to-day filter that carries its counts; a row is two lines (name and position with the status pill, what is wrong with the expected return date) behind a bar in the status color (red out, gold day-to-day) so a screenful scans before it is read; ESPN's one-line note repeated the same facts and is only the fallback when there is no detail; a tap opens the player. Tests: `tests/wire.test.ts`.
- **Power index (BPI)** (`lib/espn/power-index.ts`, `usePowerIndex`): ESPN's Basketball Power Index, the points a team would beat an average team by on a neutral court (`bpi`, split into offense and defense) with ESPN's own projection (final record, playoff / Finals / title chances in percent; `?limit=30` for all thirty teams). It is the first page of the Team Leaders pager (`BpiPage`, key `bpi`; `PAGES` in `TeamLeadersScreen`), followed by the sportsbook's title odds (`OddsPage`, key `odds`) and one page per team stat.
- **Team page order** (`TeamHome`), top down by what matters most now: team card, catch-up (own team), Home / Away / Arena, next game and form, season series against your team (a rival's page only), today's scores, the Cup standing (only while `cupIsOn`): the "on now" zone; then the team itself: the season numbers with league ranks (`TeamSeasonStats`, right after the "on now" zone: it sat below the recent games and the clips, far from the card it describes), `TeamStarCard` (the team's best player by ESPN's rating with PPG / RPG / APG, the same feed as the Team form widget; it sat between the next game and today's scores, which made the top of the page crowded and split the time-bound blocks), the last five results with a "Full schedule" link to the Calendar (it was eight: the list pushed everything else down), the clips, the odds, the watchlist (only when one of the team's players is starred), the roster button. Everything below the card is built in a second, interruptible pass.
- **Loading on demand**: drawer screens mount on first visit (React Navigation's default `lazy`), pager pages outside `windowSize` do not mount and so do not fetch, and the heavy reads are gated: the Cup (all thirty team schedules) is read on the team page only while the team's own schedule says it is on (`cupIsOn`, before it ran on every team page open all year), the odds' forty athlete records only where the names are shown, a drafted player's NBA id only for the rows on screen (`useDrafteeIdentity`), the clips and All-Star list after the page settles. Native bundles are not split by route (Expo's async routes and bundle splitting are web only), Hermes maps its bytecode lazily, and `inlineRequires` is off in Expo's Metro default (`@expo/metro-config`); turning it on was not tried: Expo's docs say nothing of it, and it can reorder module side effects (Reanimated, worklets, gesture handler) and could not be measured here.

## Form, clutch, leaders and Lock Screen
League Leaders (`LEADER_CATEGORIES` in `lib/espn/leaders.ts`, one table: ESPN category name plus how its value is read) has PPG, RPG, APG, STL, BLK, 3PM, 3P%, FG%, FT%, TOV, DD, MPG, PF and two tabs worked out in the app. ESPN sends 3P% as a fraction (rescaled in the table) and its PER has no minutes qualifier (89.2 for a rotation player), so PER is not shown: the EFF tab computes classic efficiency per game (`efficiencyOf`) from game logs. ## Loading, transitions and gestures
- Performance rules (keep them): the drawer keeps every opened screen mounted, so (1) the team state is a small external store (`state/team-store.tsx`), read with selectors (`useTeamStore((s) => s.currentTeamId)`) so changing team re-renders only what reads it, not every mounted screen; drawer screens read it with `useScreenTeamStore` (same API), which listens only while its screen is focused: the others sit still and catch up with one render when they come back into view, so a team change no longer re-renders (and re-fetches for) every screen you ever opened while the one you are leaving is still animating away; use `useTeamStore` only outside screens (the drawer menu, widget sync, providers). ## Highlights (video)
ESPN's game summary carries a `videos` array (the game's full highlights and single plays, played from the HLS stream, falling back to the one 22 MB MP4: the MP4 made the system player's 10-second skips slow, HLS is cut in short keyframe-indexed segments, adapts from 360p to 720p and has English subtitles; `normalizeVideos` in `lib/espn/video.ts`, `GameSummary.videos`). `Highlights` (`@/components`) is the row of thumbnails with a full-screen player (`HighlightPlayer`, `expo-video`) and is used on the game Summary tab, the team page (`TeamHighlights`: full-game clips of the last four finished games) and the player's Season tab (`PlayerHighlights`: clips from his last six games whose headline names him; ESPN has no per-player or per-team video feed, I tried several). It reads each game's summary through the same cached query the game page uses (`useGameVideos`). ESPN lists the countries each clip is licensed for and Spain is on none of them; `HONOR_VIDEO_REGIONS` (false) decides whether the app respects that list. It is false because this is a personal practice app and its owner chose to show them anyway: flip it to true if the app is ever shared. `expo-video` is a native module: `Highlights` probes for it (`requireOptionalNativeModule('ExpoVideo')`) and shows a "needs a new build" message on a build made before it was added, instead of crashing; after `npx expo install expo-video` run `npx expo prebuild --platform ios --no-install`, `pod install` and a native build.
The player (`HighlightPlayer`) is the system's own full-screen video player: a 1-pt invisible `VideoView` is mounted and sent to full screen with `enterFullscreen()`, so the controls, the close button and the rotation are all the system's and nothing of ours sits on top (a custom control layer, then a custom close button, were tried and dropped); when it is dismissed (`onFullscreenExit`) the row closes it, and a clip that ends goes on to the next. Loading: the system player is presented only once the clip has its first picture (`statusChange` → `readyToPlay`); until then the tapped thumbnail shows a veil with a spinner (`phase` 'loading'), and a tap on another clip meanwhile only swaps the source of the same player (`useVideoPlayer` calls `replaceAsync`, which cancels the download in flight). Opening clips one after another used to leave a black full-screen player frozen on its first second: each tap built a new player buffering 60 s of HLS at once, and presenting over a system player still being dismissed never started (`REPRESENT_GAP_MS` now spaces them). A clip that errors or has no picture after 15 s shows "Couldn't load" on its thumbnail with Retry (remounts the player through `attempt`) and "ESPN ↗" (`GameVideo.webUrl`, the clip's espn.com page, opened with `expo-web-browser`). Quality: ESPN's HLS master playlist lists eight levels, lowest (360p, 0.7 Mbps) first, and the player starts on the first and takes four or five seconds to climb (measured with AVPlayer's access log), so every clip began blurry. `sharpSource` (`lib/espn/video.ts`) reads the master playlist while the thumbnail shows its loading state and the player is given the 720p, 30 fps level with the lowest bitrate directly (`sharpestVariant`; about 2.7 Mbps average, a 16 s clip is about 5 MB), sharp from the first frame; if the read fails it falls back to the master stream. Cost: no adaptive down-shifting on a weak connection and no subtitles (they hang off the master playlist). A local master playlist with the 720p level listed first was tried and AVPlayer would not load it from a file. While the clips of the team and player rows are read (the `useAfterSettle` pause plus a few requests) `Highlights` draws its title with placeholder cards (`loading`, `Highlights.skeleton.tsx`, same measurements as the real row) so nothing below moves; it collapses if there turn out to be none. Placement: the game page puts the clips first on a finished game and after the leaders on a live one, the team page puts them right under Recent Games (results, then the clips of those games), the player's Season tab right after his Form card (how he is playing, then the clips from those games). The calendar's Finals and All-Star marks are keyed by the device's day like its cells (`calendarEvents`, `easternEveningKey` for the All-Star Game, whose tip-off time is not known: 8 pm Eastern). Caching is deliberately not used: expo-video cannot cache HLS on iOS (`useCaching` is for progressive files only), and the MP4 is about 22 MB per 16 s clip against a few MB of 360p HLS. The whole app stays locked to portrait for good (`expo-screen-orientation` plugin, `initialOrientation: PORTRAIT_UP`; `orientation` in `app.json` is `default` so the native project allows landscape at all): only the system player rotates, because expo-video's own full-screen view controller sets its supported orientations (`fullscreenOptions.orientation: 'default'`). Unlocking the app while the video was open broke the layout when it closed in landscape, so the app never unlocks. Needs `expo prebuild` + `pod install` + a native build after the orientation change. `expo-screen-orientation` is pinned to 58.0.3: 58.0.4 uses `ExpoRootViewController`, which the installed `expo-modules-core` (58.0.29) does not have, and the iOS build fails; move both together.

## Performance and stability
- **The first visit to a drawer screen is paid for in the background** (`usePreloadScreens` in `navigation/preload.ts`, used by `(drawer)/_layout.tsx`: `PRELOADED` = Calendar, Team Leaders, Teams, then `PRELOADED_LATER` = Player Leaders, through `router.prefetch`, which renders a drawer screen without focusing it; it only works for a drawer that is the active route, a `prefetch` made from the intro route through a preloaded `/home` remounted the Calendar in a loop). Measured in the simulator with a temporary frame-gap meter and React `Profiler` (JS stalls and UI frames over 26 ms per 250 ms window): a cold first open of the Calendar blocked the JS thread for 177, 330 and 359 ms while it slid in (mount 63 ms of React work, the rest native view creation and layout, plus three more renders during the slide) and dropped several UI frames; the same open after a preload has no mount at all, one JS stall of about 85 ms and one slow UI frame (the menu closing), the same as a second visit. Timers, `useSceneSettled` and prefetching only move work around inside that window; the mount itself is the cost, so move it out of the open. A preloaded screen is unfocused when it mounts, so `SceneFrame` treats it as settled and its second pass (day strip, neighbouring pages, prefetches) runs then too. Add a screen to `PRELOADED` when its first open stutters, and measure it the same way (temporary `Profiler` + `useFrameCallback` meter, `xcrun simctl spawn <udid> log stream --predicate 'eventMessage CONTAINS "[probe]"'`; truncating the log file while `log stream` writes to it leaves NUL padding, so read it through `tr -d '\000'`). **The intro is an overlay, not a route** (`IntroOverlay`, `features/intro/components`, mounted by the root layout when a launch starts on `/`; `IntroScreen` is only the blank route under it), and the app is built underneath it, never while anything moves (building a screen freezes whatever is animating: a timer from the screen's mount landed the home card on the last bounce, starting after the bounce landed it on the ring, and acts with a still beat between them made the intro 4 to 5 s). So `run()`: the native splash is still up (a still picture of the ball) and under it `router.replace('/home')` builds the drawer and the home card (`whenIdle(300, 200)`, capped at 2 s); then `SplashScreen.hide()` and one short continuous animation (`ANIM_MS` 1.6 s: toss and bounces 1.0 s, the court line, the ring from 0.78 s, the wordmark from 0.9 s, the ring's echo from 1.1 s); then, with the finished logo still, `preloadWithin(STEP_BUDGET_MS = 600)` builds Calendar, Team Leaders and Teams one at a time (`preloadStep`, each `whenIdle(150, 100)`: at least that long, then that much quiet counted from the last frame more than 24 ms late): a step that has begun is finished, none begins after the budget, and `endPreloadDrive()` (called as the intro leaves) hands what is left to timers (1.5 s and 1.2 s apart); then the fade (0.32 s). The budget is what keeps the intro short on a slow device, whatever the screens cost. `PRELOADED_LATER` (Player Leaders, light) is built 4.5 s after the drawer mounts. The root layout does not hide the splash while the intro is up (the route changes to `/home` under it); the intro does. A tap skips the animation and the remaining steps. Measured in the simulator (dev): home built under the splash in 1.1 s, animation 1.6 s, one step (the Calendar) in the budget, then the fade: about 2.7 s of animation and fade after the splash goes, 3.8 s in all; a Release build builds faster, so the splash part shrinks and more steps fit (estimated 3 s or less in all, not measured). A first launch (no favorite team) has no drawer to build and goes on to `/onboarding` as before. A launch that a widget, the Dynamic Island or a link opens on another page has no intro (the root layout hides the splash).
- First open of a drawer screen: every drawer screen is mounted on first visit while the menu closes and `SceneFrame` slides it in (520 ms). Its heavy second pass (the rest of a list, a neighbouring pager page, a prefetch, a second pane) must start after that slide, and `useSceneSettled(padMs)` (`@/hooks`, fed by a context that `SceneFrame` provides; true for good once the slide is over, true at once off the drawer and on the first screen after launch) is how: Teams, Team Leaders, Calendar (`DayPager`, `DayPills`), League Wire and Playoffs use it instead of their own timers (350, 700, 900 ms: the shorter ones landed mid-slide). - Not changed, deliberately: the Roster strip's per-pill animations (30 pills, two small worklets each, they exit early away from the highlight), the drawer keeping opened screens mounted (freezing them left a blank background).
- Calendar first open (measured in the simulator, cache cleared: worst UI frame 84-92 ms -> 33 ms): `DayPills` draws only the 17 days around the selected one until `useSceneSettled(150)` and then all 66; `DayPager` builds the neighbouring days 300 ms after the slide-in from the menu is over (`OPEN_MS` on top of `useSceneSettled`) and prefetches ±1, ±2 days one at a time 350 ms apart; `DayPage` is `IdlePage` (plain skeleton, none of the data hooks) or `LivePage` (hooks and cards): a page that is only waiting or being scrolled past must not set up queries. `extraData` of the pager list is memoized. Measure with React `Profiler` plus the meter, not by feel.

- **Changing the favorite team goes back to the app, it does not replace it.** The team card's star and the drawer push `/onboarding` over the drawer; `OnboardingScreen` confirms with `router.dismissTo('/home')` (pops to the drawer that is still under it; on a first launch, where nothing is under it, it replaces). `router.replace('/home')` mounted a second whole drawer (every screen, widget sync, queries) on top of the first on each change, and the app lagged after about a dozen quick changes. Not yet confirmed on a device.

- **The game page's logo slots are measured relative to the header, not the window.** `ScoreHero` reports each slot with `measureLayout` against its own root, and `GameScreen` adds the scroll frame's place (`frame`); no scroll offset is involved. It used `measureInWindow` plus `scrollY.get()`, and a refresh (which holds the page pulled down while new data re-lays-out the header) could measure at one offset and correct with another, so the logos jumped. Not reproduced in the simulator (it needs a score change during the pull); fixed by removing the dependence.

- **Spacing on the game tabs is one rhythm**: sections are 16 pt from the sides, 14 pt apart (`marginBottom` on the section, none above), their label 8 pt above the card; every tab's content starts 12 pt under the tab bar (`content` paddingTop), and the Box score, Plays and Shots filter rows are 12 pt above what they filter. `Highlights` takes `section` and `HeadToHead` takes `flush` to follow it on the Summary (their own margins are for other screens).
